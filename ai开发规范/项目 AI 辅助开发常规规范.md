# AGENTS.md

## AI 辅助开发常规配置

本项目允许并鼓励使用 AI 辅助开发，但 AI 生成或修改的代码必须经过人工确认，并纳入与普通代码相同的 Git、测试和 Review 流程。

### 一、任务执行流程

处理开发任务时遵循以下顺序：

1. 明确需求、约束条件和验收标准。
2. 先分析现有代码和相关配置，再提出实施计划。
3. 涉及多个文件或较大改动时，先让人工确认计划。
4. 小步修改，避免顺手修改与需求无关的文件。
5. 每完成一个可验证步骤，及时运行对应测试或检查。
6. 修改完成后检查完整 diff，并由人工 Review。
7. 通过质量检查后再提交 Git Commit 或 Pull Request。

### 二、AI 开发记录要求

每次 AI 辅助开发完成后，必须保留可追溯信息；不要求保存完整对话记录。

#### 小型修改

在 Git Commit 或 Pull Request 描述中记录：

- 需求或问题
- 实际修改内容
- 测试或验证结果

#### 中大型功能、重构和线上问题

在 `AI辅助开发/记录/` 下新增一份 Markdown 记录，文件名建议使用：

```text
YYYY-MM-DD-功能或问题名称.md
```

至少包含以下内容：

- 需求背景与验收标准
- AI 参与的工作范围
- 人工确认的方案与关键决策
- 实际修改的文件和主要变更
- 测试、Lint、类型检查或构建结果
- 人工 Review 结论
- 已知风险、遗留问题和后续事项

可使用 `AI辅助开发/AI开发记录模板.md` 作为模板。

### 三、必须人工重点检查的内容

以下代码不得仅依赖 AI 输出，必须进行人工 Review：

- 身份认证、权限控制和数据访问
- 支付、订单、计费和资金相关逻辑
- SQL、数据库迁移和数据删除操作
- 加密、密钥、Token 和隐私数据处理
- 并发、缓存、消息队列和分布式一致性
- 依赖引入、供应链和网络请求
- 生产环境配置及部署脚本

### 四、安全与依赖约束

- 不得向 AI 提供密码、Token、私钥、客户数据或其他敏感信息。
- 新增第三方依赖前，必须人工确认包名、来源、版本、许可证和安全状况。
- 不得把 API Key 或其他凭据写入代码、记录、日志或提交历史。
- 记录中只保留必要的技术信息，不保存完整的敏感上下文。

### 五、质量门禁

AI 生成的代码必须满足项目现有的质量要求，包括但不限于：

- 格式化与 Lint
- 类型检查
- 单元测试和集成测试
- 构建验证
- 安全检查
- Git Diff Review

如果项目暂时没有自动化检查，应在 AI 开发记录中明确说明，并记录人工验证方式。

### 六、规则沉淀

如果 AI 在项目中反复出现同类错误，或任务形成了稳定的工程约定，应更新本文件或其他项目规则文件，避免重复纠正。
