# 使用 AI 开发代码：主流模式、环境配置、工作流程与注意事项

> 整理日期：2026-09-22
> 适用场景：个人开发者 / 小团队，在企业或开源项目中引入 AI 辅助编码

---

## 一、当前主流模式（按介入深度从浅到深）

### 1. 代码补全（Inline Completion）
- **代表工具**：GitHub Copilot、Cursor Tab、通义灵码、CodeGeeX、Continue
- **形态**：IDE 内 Tab 补全，写一行提示下一行
- **适合**：样板代码、重复逻辑、单测骨架、注释转代码
- **成本**：最低，几乎零学习成本；但只能做"局部小步"

### 2. IDE 对话式（Chat in IDE）
- **代表工具**：Cursor Chat、GitHub Copilot Chat、Windsurf、Trae、JetBrains AI Assistant
- **形态**：在编辑器里用 `@文件` 指定上下文提问，AI 直接给出 diff
- **适合**：理解陌生代码、局部重构、解释报错、生成测试
- **关键点**：**上下文给得准，答案质量差 10 倍**——明确指定相关文件

### 3. Agentic 编程（自主智能体，当前最热）
- **代表工具**：Claude Code、Cursor Agent、OpenAI Codex CLI、Gemini CLI、Aider、OpenHands、Devin
- **形态**：给一个任务，AI 自主读文件 → 改代码 → 跑命令 → 跑测试 → 提交 git
- **适合**：中大型功能开发、批量重构、修复杂 bug、迁移升级
- **三个核心机制**：
  1. **Plan 模式**：先出方案再动手，人工批准
  2. **权限审批**：命令执行需确认 / 白名单 / 全自动三档
  3. **沙箱**：在隔离环境跑命令，防止误伤系统

### 4. 异步云端 Agent
- **代表工具**：Devin、Codex Cloud、Google Jules、GitHub Copilot coding agent
- **形态**：把 issue 派给云端 Agent，异步执行后产出 PR，人只负责 review
- **适合**：并行处理多个小任务、团队批量化提效

### 5. 代码评审 / 质量类
- **代表工具**：CodeRabbit、Greptile、Copilot Code Review
- **形态**：对 PR 自动 review，找 bug、安全漏洞、风格问题
- **定位**：作为人工 review 的"第一道过滤器"，不能替代人工

### 6. 企业私有化部署
- **代表方案**：vLLM / Ollama + 开源模型（Qwen、DeepSeek 等）+ 内部网关
- **适合**：代码不能出内网的合规场景
- **权衡**：能力略低于顶级闭源模型，但数据可控

## 二、需要配置什么

### 1. 账号与密钥
| 方式 | 说明 |
|---|---|
| 订阅制 | Copilot / Cursor / Claude Code 等按月订阅，开箱即用 |
| API Key | OpenAI / Anthropic / Google / DeepSeek，按 token 计费，灵活 |
| 国内可用 | 通义灵码、文心快码、CodeGeeX、DeepSeek API（无需代理） |
| 企业统一网关 | 统一中转、统一计费、统一审计，避免个人 key 散落 |

**密钥管理红线**：密钥只放环境变量或密钥管理服务，**绝不写进代码库**。

### 2. 网络与环境
- 海外模型通常需要代理；企业内网需要白名单 / 专线
- 私有化部署：本地推理服务 + 反向代理（对上层工具暴露 OpenAI 兼容接口）
- **先确认公司合规政策**：源码是否允许上传第三方服务

### 3. 工具链与 IDE
- **插件派**：VS Code / JetBrains + AI 插件（改造现有习惯）
- **独立 IDE**：Cursor / Windsurf / Trae（体验最完整，需迁移）
- **CLI 派**：Claude Code、Aider、Codex CLI（终端里跑，适合服务器 / 无 GUI / 脚本化）

### 4. 项目上下文文件（最重要的一项配置）
在仓库根目录放一个"给 AI 看的说明书"：

| 工具 | 文件 |
|---|---|
| Claude Code / Codex | `AGENTS.md` / `CLAUDE.md` |
| Cursor | `.cursor/rules/*.mdc` |
| Copilot | `.github/copilot-instructions.md` |

**建议内容**：
- 技术栈与版本（Node 20、React 18、pnpm…）
- 目录结构与职责划分
- 构建 / 测试 / lint 命令（AI 要自己跑）
- 代码规范与命名约定
- **禁止事项**（如"不要动 legacy/ 目录"、"不要引入新依赖"）

> 这是让输出从"能跑"提升到"符合项目规范"的最大杠杆，越具体越好。

### 5. 模型与参数
- **选型**：强推理模型做架构 / 复杂重构；快速模型做补全 / 小改
- **上下文窗口**：大仓库装不下全部代码，需要 @ 指定文件或 RAG 检索
- **成本**：按 token 计费，长上下文任务要节制

### 6. 安全与权限
- 命令执行审批档位：每次确认 → 白名单 → 全自动（**从保守开始**）
- 沙箱运行：容器 / 虚拟机隔离，防止误删文件、误跑危险命令
- 忽略文件：`.gitignore` / `.aiignore` / `.cursorignore` 排除密钥、生产配置
- MCP 工具接入（数据库、Jira、Figma 等）：**最小权限原则**

### 7. 质量闸门（AI 产出的验收机制）
- lint / format / 类型检查 / 单元测试
- pre-commit hook 自动跑
- CI 全量验证，红灯不许合并

### 8. 可观测性
- 用量与成本统计
- 记录 AI 常犯的错，反过来迭代上下文文件

## 三、推荐工作流程

```
需求拆解 → AI 探索出计划 → 人工评审计划 → 小步实现（每步跑测试）
   → 人工 review diff → 跑 CI → 提交 PR → 复盘沉淀到 rules 文件
```

### 分步说明

1. **准备**：git 工作区干净，切出新分支（AI 改乱了能一键回滚）
2. **写清任务**：像写 ticket 一样写需求 + 验收标准，模糊需求 = 垃圾输出
3. **探索阶段**：让 AI 先读代码库，产出"理解 + 方案"，**先不写代码**（Plan 模式）
4. **人工评审方案**：确认技术路线、影响范围、有没有更简单的做法
5. **执行阶段**：小步实现，**每一步都跑测试/lint**，不要一口气改 20 个文件
6. **评审 diff**：逐处看改动，重点看边界条件、错误处理、安全
7. **验证**：全量测试 + CI 通过
8. **提交 PR**：可让 AI 起草变更说明，人工润色
9. **复盘沉淀**：把踩的坑写回 `AGENTS.md`，把重复流程做成命令 / 技能

### 核心心法
> **小步、可验证、可回滚。** 把 AI 当成一个很快但需要 review 的初级工程师，而不是权威。

## 四、注意事项与常见坑

1. **幻觉 API**：AI 会编造不存在的函数、包名、配置项
   - 危险变体：**slopsquatting**——攻击者抢注 AI 常编造的包名投毒
   - 对策：新依赖必须去官方源核实

2. **上下文失控**：不限定范围，AI 会"顺手改一堆无关代码"
   - 对策：明确说"只改 X 文件"、"不要动 Y"

3. **安全漏洞**：AI 生成的代码常有注入、越权、硬编码密钥问题
   - 对策：安全相关代码（认证、支付、SQL）必须人工逐行审

4. **不要粘贴敏感数据**：密钥、生产数据、客户信息不要发给模型

5. **许可证合规**：企业项目注意 AI 生成代码的版权风险，遵守公司政策

6. **别盲信 AI 写的测试**：它可能"迎合实现"而非验证需求
   - 对策：测试的断言逻辑也要人工过一遍

7. **认知债**：长期不读 AI 写的代码 → 逐渐失去对系统的理解
   - 对策：核心模块必须自己吃透，AI 代码要能讲明白才合并

8. **大改动先计划后执行**：直接说"帮我重构整个项目"必然翻车

9. **成本控制**：长上下文 + 多次重试 = token 快速燃烧，按需选用模型

10. **团队一致性**：统一 rules 文件、统一工具链，否则团队风格割裂

## 五、快速上手 Checklist

- [ ] 选定工具链（插件 / 独立 IDE / CLI）
- [ ] 配置账号与密钥（企业走统一网关，密钥不进代码库）
- [ ] 仓库根目录创建 `AGENTS.md`（或对应规则文件），写清技术栈与命令
- [ ] 配好 lint / test / CI 作为验收闸门
- [ ] 配置忽略文件，敏感文件不上传
- [ ] 命令执行从"每次确认"档开始，逐步放开
- [ ] 从低风险任务起步：写测试 → 修小 bug → 小功能 → 逐步放大
- [ ] 团队共识：**AI 产出必须人工 review 后才能合并**

---

## 六、一句话总结

> 主流形态是 **Agentic 编程**（Claude Code / Cursor Agent / Codex CLI 等），
> 配置的核心是 **上下文文件 + 质量闸门 + 权限沙箱**，
> 流程的核心是 **先计划、小步走、人工把关**，
> 最大的坑是 **盲信输出**——AI 是加速器，不是责任人。
