## 2 一周一句话（每讲压成一句，用来回忆）

1. **少样本提示**：给几个"输入→输出"的范例，比空口描述规则管用；**范例要覆盖边界情况**，且**顺序与格式有一致性**才有稳定收益。
2. **思维链（CoT）**：让模型"先想再答"能提升推理准确率，但**推理 token 也计费、也占预算**——推理模型的 `max_tokens` 是"**推理 + 正文**"共享（本机实测给 48 时正文直接是空串）。
3. **结构化输出**：`response_format` 的 json_schema / json_object **本机端点接受但不强制**——**护栏必须建在"本地校验 + 失败重试"里，不能依赖参数**。
4. **Function Calling**：模型不直接执行，只输出**结构化的调用请求**；它是"**模型 ↔ 你的代码**"的协议，**安全边界（白名单、参数校验、幂等）必须由你守**。
5. **文本切片**：**检索的最小单位 = 切片的最小单位**；chunk 太大向量被平均、太小语义碎片化，`overlap` 是救命绳但**一定小于 size**。
6. **向量检索**：把"意思像不像"变成"**夹角小不小**"；**入库与查询必须同一模型**；**精确串（型号/编号）关键词更强**，生产多为混合检索。
7. **重排（Rerank）**：召回（双塔）快而粗、重排（交叉编码器）慢而准；**重排的上限由召回决定**，它救不了召回没召到的。

## 3 本周实测数据（自己的机器上跑出来的，不是抄的）

**能说出自己实测数字的人和只会背概念的人，是两类人。**

| 实测项 | 结果 |
|---|---|
| 端点参数兼容性（DHwork OpenAI 兼容端点） | `gpt-5.6-terra-dhwork` 传 `temperature` → **400 Unsupported parameter**；推理模型不收温度 |
| `response_format: json_schema(strict)` | **200 但不强制**：提示词不明确要求时 3/3 次返回**自然语言** |
| 流式结束标记 | **不发 `data: [DONE]`**，也不返回 usage → 结束只能靠连接关闭判断 |
| 切片：定长 vs 递归（size=600, overlap=120，对 11-05 材料） | 递归**孤儿块数=0** / 定长=1；**开启 overlap 后实际块长 ≈ size+overlap**（实测最长 717） |
| 向量维度 | `bge-m3` = **1024 维**；`text-embedding-3-small` = **1536 维** |
| 向量检索（5 条文档，"怎么让检索结果更准？"） | 无共同词的"重排能提升精度"被排到 **#1（cos=0.6222）**；跑题的压到 #4/#5 |
| 重排改序（"为什么不能只靠向量相似度？"） | 向量把"最常用、效果好"的错误答案排 **#1**；重排把正确答案**从 #2 拎回 #1**，并把不相关的打到 **0.006 / 0.005** |
| 引用校验（4 条陈述） | 裁判模型**抓到全部 2 条幻觉**（说反、编数字）；**字面 bigram 覆盖抓不住"说反"**（那条覆盖率仍高达 0.429） |

## 5 本周暴露的三个薄弱点（下周针对性补）

1. **"护栏建在参数上"的惯性还在**。结构化输出那讲实测到"`json_schema` 不强制"才回过神——**凡是"依赖模型自觉"的地方都不能信**，必须本地校验。→ 下周做 RAG 评估时，要把"**校验通过率**"也变成一个可测指标。
2. **"召回没做好就怪重排"**。11-08 的"召回天花板"实验说明：**问题定位的顺序永远是"先召回、后重排、再生成"**。→ 需要一套 **badcase 归因流程**，而不是凭感觉调参。
3. **成本意识还没变成习惯**。本周算了 token、算了向量维度，但**没有把"每次改动的延迟/成本"记成固定数字**。→ 下周起，每个动手任务**至少留一个实测数字**。

## 8 一句话复盘（本周）

> 这一周把 RAG 的"上半条链路"打通了：**切片 → 向量 → 重排**。最大的收获是理解了**"分工"**——每一环都在用不同的成本换不同的质量（切片换语义完整、向量换召回覆盖、重排换排序精度），**没有哪一环能一步到位**。工程上的功夫，全在"**每一步都知道自己在牺牲什么、换取什么**"。
