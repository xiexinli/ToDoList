## 1 概念精讲（30 min）
### 一句话定义
**结束确认是一个证据协议**：取消意图先阻止结果展示；资源占位直到匹配当前操作、可信来源、已终结且资源释放可确认时才解开。超时只表示观察期结束，不能替代后端终结证据。

### 为什么现在必须懂
昨天已把云端授权绑定到具体输入，但如果本地调用还没停，用户点“换云试试”，两个请求可能同时执行。只禁用一个按钮挡不住页面重建、另一入口或新请求ID。要把限制放在共同的执行协调器，并明确其覆盖的资源域，例如同一模型客户端或同一份编辑任务，而不是误禁整个App所有无关工作。

取消时首先停止采纳结果，保留用户原文；再向现有任务发送取消意图。这个顺序避免取消信号传递期间迟到正文又覆盖编辑框。示例不真正发取消，只演示接入层处理事件的策略。用户可以继续手动编辑，不必被一个未知后台状态锁住整个页面；被锁的是新增推理执行，不是人工输入。

### 四种状态，不能用一个 isLoading
| 状态 | 已知事实 | UI与新增执行 |
|---|---|---|
| RUNNING | 当前操作已占位，尚无终结证据 | 可预览草稿；相同/新ID均不另开执行 |
| CANCEL_REQUESTED | 已记录取消意图，未确认终结 | 立即隔离草稿，显示“正在取消”；仍占位 |
| UNKNOWN | 超时、断联或结束证据不足 | 显示“结束尚未确认”；不以新ID换后端 |
| 已确认终结 | 同操作可信回执，终结/释放证据齐备 | 解锁新意图；不自动重启，不复用旧ID |

```text
用户取消 → 关闭本次结果展示 → 通知原任务（由适配器实施）
                          ↓
           取消中 / 超时或断联记UNKNOWN；仍保留占位
                          ↓
同请求ID + 原后端 + 可信回执 + 已终结 + 释放证据
           ├─ 缺一项 → 保留占位，继续人工编辑/核对
           └─ 齐备 → 解锁；下一次仍需新的用户意图与授权
```

### 官方契约与应用策略分开
- ML Kit `GenerativeModel`文档说明收集Flow的协程可取消，`close()`用于释放相关引擎资源。**文档没有在此给出“调用cancel后X毫秒设备一定停止”的保证**，本课也没有实测。不要造一个成功回调或固定延时当释放凭证。
- Kotlin `Job.kt` 1.7.3源码将 Cancelling 与 Cancelled/Completed 区分；取消中不是完成态。当前在线 `cancelAndJoin` 参考（页面标1.11.0）说明它先取消并挂起等待Job完成，而且等待者自己的取消仍会抛 `CancellationException`。这是协程生命周期契约，不是远程HTTP服务已经停止的证明；本课不安装该版本，不验证与旧SDK版本组合。
- `cancelAndJoin`可能因非协作任务或清理耗时而等待；不要在主线程用阻塞join。外层等待预算耗尽后仍记UNKNOWN，不用“终于退出等待了”解锁。受控清理可按工程设计使用专用作用域，但不能以不可取消清理让整个任务永不结束；这里不增加新的Android实现片段。

### 可信回执要绑定什么
原请求ID和原后端必须匹配；查询/回调来自事先批准、身份可靠且语义明确的适配器。远程查询要区分“取消请求已收下”“操作已失败终结”和“暂时查不到”。404、连接断开、客户端收到取消异常，都不能统一当“远端未执行”。没有查询契约时保留未知，不猜。

示例的 `verified/ended/released` 全是**人为测试输入**，生产不得直接信任外部JSON里的同名布尔值。标记应由真正验证响应身份和语义的适配层构造；它既不实现签名验证，也不提供远端取消/查询API。仅检查来源字符串不是认证。端侧释放可确认的条件也需按实际SDK契约与验证路径设计；只调用 `close()`，本课不声称已证明GPU/NPU停止。

### 迟到成功和恢复
用户取消/超时后，即使后端稍后返回成功，也只用可信终态回执解除占位；不能恢复展示或自动采纳旧草稿。开始新任务后，旧请求的回执/正文不得清空新占位、追加到新草稿。输入修改先关闭旧结果通道，再处理取消；新用户意图不绕过旧在途限制。

同进程锁只实现当前协调器的互斥。多个实例、进程被杀、App重启、跨设备和服务端重放需要持久操作账本及服务端契约；本例都未实现。不能称 exactly-once，也不能清空内存表当恢复完成。

### 常见误区与30分钟自问
1. “cancel返回就能重试”——返回通常是意图提交，要看明确终结路径。
2. “改ID就不是重复请求”——旧工作未结束，仍占用相同资源；相同和新ID要各测。
3. “收到迟到成功就交付更友好”——用户已经取消采纳；解锁不等于交付。

## 2 代码片段（40 min）
- 场景：给便签生成按钮定义可复跑的结束确认契约，不连接任何真实后端。
- 依赖与版本：本机CPython 3.9.6；`dataclasses/threading/unittest`标准库，无pip、SDK或凭据。主代码如下，保存为`end_guard.py`直接运行。
- 验证边界：Host固定回执；Android编译、Nano/云请求取消、实际释放时间与真实usage均NOT_EXECUTED。没有模型调用，因此无可报告的模型Token或性能数据。
```python
# -*- coding: utf-8 -*-
"""Host固定事件：不发取消/不查询SDK；回执必须由可信适配层验证。"""
from dataclasses import dataclass
from threading import Lock

@dataclass(frozen=True)
class Receipt:
    rid: str
    backend: str
    source: str
    outcome: str
    ended: bool = False
    released: bool = False
    verified: bool = False

class EndGuard:
    def __init__(self):
        self.lock = Lock()
        self.active = None  # 资源域占位，不只是同一个ID去重
        self.used = set()
        self.state = 'IDLE'
        self.discard = False
        self.draft = ''

    def start(self, rid, backend, approved=False):
        with self.lock:
            if approved is not True or not isinstance(rid, str) or not rid:
                return 'DENY'
            if backend not in ('LOCAL', 'CLOUD'): return 'DENY'
            if rid in self.used: return 'DUPLICATE'
            if self.active is not None: return 'BLOCKED_IN_FLIGHT'
            self.active = (rid, backend)
            self.used.add(rid)
            self.state, self.discard, self.draft = 'RUNNING', False, ''
            return 'STARTED'

    def fragment(self, rid, text):
        with self.lock:
            if (self.active is None or self.active[0] != rid
                    or self.state != 'RUNNING' or not isinstance(text, str)):
                return 'DROP'
            self.draft += text
            return 'PREVIEW'

    def interrupt(self, rid, kind):
        with self.lock:
            if self.active is None or self.active[0] != rid: return 'IGNORE'
            if kind not in ('CANCEL', 'TIMEOUT', 'LOST'): return 'DENY'
            self.discard, self.draft = True, ''
            # 已未知不能因再次点击取消而倒退成“快结束了”。
            if self.state != 'UNKNOWN':
                self.state = 'CANCEL_REQUESTED' if kind == 'CANCEL' else 'UNKNOWN'
            return self.state  # 不释放占位，也不自动换后端

    def confirm(self, receipt):
        with self.lock:
            expected = {'LOCAL': 'LOCAL_ADAPTER', 'CLOUD': 'REMOTE_STATUS'}
            if (self.active != (receipt.rid, receipt.backend)
                    or receipt.source != expected.get(receipt.backend)
                    or any(v is not True for v in
                           (receipt.verified, receipt.ended, receipt.released))
                    or receipt.outcome not in ('SUCCESS', 'FAILED', 'CANCELLED')):
                return 'REJECT_RECEIPT'
            # 回执表明任务终结，不表示结果可展示；已取消的迟到成功不能复活。
            self.state = 'ENDED_SUPPRESSED' if self.discard else 'ENDED_' + receipt.outcome
            if self.discard or receipt.outcome != 'SUCCESS': self.draft = ''
            self.active = None
            return self.state

if __name__ == '__main__':
    g = EndGuard()
    print(g.start('a', 'LOCAL', approved=True))
    print(g.interrupt('a', 'TIMEOUT'))
    print(g.start('b', 'CLOUD', approved=True))
    print(g.confirm(Receipt('a', 'LOCAL', 'LOCAL_ADAPTER', 'SUCCESS', True, True, True)))
    print(g.start('b', 'LOCAL', approved=True))
    print('Host固定事件；真实后端调用=0，SDK取消/资源释放/usage均未测')
```

### 逐行要点与踩坑
- `active`锁的是资源域，不只是`used`里的ID；新ID也必须经过它。
- `interrupt`只变状态与展示策略，不设置`active=None`。UNKNOWN再次取消仍未知。
- `confirm`核验的是可信适配层提供的同操作回执；`True`检查拒绝未知，不替代身份验证。
- `discard`独立于后端终态：取消后即使终结为SUCCESS，也清草稿并只解锁。
- 锁外应实际执行模型，锁内只做短操作；本例完全不启动模型。当前类不暴露完整生产事件持久化，不能用它证明设备侧取消正确。
