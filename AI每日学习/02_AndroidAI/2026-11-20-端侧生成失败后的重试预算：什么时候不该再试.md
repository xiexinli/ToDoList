## 1 概念精讲（30 min）
- **一句话定义**：重试预算是针对同一次用户意图，限制允许重新执行的失败类别、次数及累计时间的应用策略。
- **为什么现在必须懂**：昨天能测出慢在哪，今天要决定慢和失败之后是否继续。手机上的模型不是无限供应的服务器；前台资格、服务配额、取消状态和残留正文都可能改变下一次调用的合法性。把所有异常包装成“网络不稳定”会增加耗电，让用户退出页面后仍等待，还可能把被安全检查拒绝的输入一遍遍提交。工程目标不是尽量获得一段文本，而是在用户仍需要且系统允许时完成请求，否则可靠地停下来。

### 关键机制：默认STOP的保守允许名单
```text
失败返回 → 判错误类别 → 确认前台/已结束/资源释放/无部分正文
       → 检查业务策略 → 服务给出正且有效的retryDelay
       → 次数与累计预算足够 → 可取消等待 → 执行前再次校验 → 再试
任一环节未知或否定 → STOP，交回编辑界面，不自动上云
```
这里“已结束”和“资源释放确认”是你的接入层需要提供的事实，不是看见异常就推出来的结论。收到应用层超时只表示观察窗口结束；底层工作可能仍在跑。取消信号发出也不等于设备已释放资源。接入契约无法证明时宁可停，保留取消中或结束未知状态；不要拿一个定时器把未知强行改成已结束。确认应来自相应任务完成/清理的可信路径，今天不伪造SDK的释放回调。

**官方事实与应用建议分开**：错误参考里BUSY＝9可能表示用量配额不足，也可能表示不允许的后台使用。因此9不是网络错误，更不是自动放行证据。概览还明确要求应用处于最上层前台；前台服务不是最上层前台。今天只允许9作为候选，并要求明确前台、请求已结束、资源释放确认、无部分正文、业务允许及正有效的retryDelay同时满足。这是一条有意偏严的应用建议，不是宣称SDK保证满足这些条件后必定成功。

| 类别 | 官方语义 / 本课处理 |
|---|---|
| 9 BUSY | 原因混合；仅进入保守允许名单评估 |
| 4 REQUEST_PROCESSING_ERROR | 请求未通过某些policy检查；停止，不当网络错 |
| 11 RESPONSE_PROCESSING_ERROR | 响应未通过policy检查；停止，清除不安全残留正文 |
| 15 RESPONSE_GENERATION_ERROR | 模型因请求policy检查不能生成；停止 |
| 7 CANCELLED | 已取消；尊重用户意图，不在catch里复活 |
| 后台限制、长期配额、未知代码 | 今天全部停止；不能凭异常文案猜测可恢复 |

11/15可能打断流式输出，官方建议考虑从UI移除不完整结果。产品上可以显示“本次生成未完成，请手动编辑”，但不可把残留内容当作已安全完成的答案。即使其他错误留下部分正文，今天策略也停止，避免重试把两个候选拼接起来。无正文不是“空白字符个数为零”的巧合，应由接入层根据真实输出状态提供。

### 时间账：次数包括首次，等待也花预算
建议总尝试数为2，即首次加最多1次重试；建议累计预算2500毫秒，单次操作预留900毫秒。数字只是固定练习值，不是SDK默认、设备指标或生产推荐。记第一次受理的单调时刻，后续每次用同一时钟算已耗时；输入改变属于另一用户意图，不应偷偷刷新同一请求的预算。

判定式：`已耗时 + 向上取整的服务等待 + 下一次操作上限 ≤ 总预算`，同时`已开始次数 < 最大尝试数`。服务建议1234.1毫秒时等1235毫秒，不能转成1234，也不能为赶预算把它压成500。已耗100毫秒时可容纳下一次；耗500毫秒时总计2635，必须停止。零延迟表示未知或不适用，不是鼓励立即再试；负数、无穷和NaN也不放行。

实际工程可把本地退避与服务下限取较大值，加入抖动也不能低于服务下限；今天不实现这一延伸。操作预留只是准入条件，真正执行还要遵守整体截止时间。操作超时后不再尝试，但仍需管理未结束的工作；预算不是杀死底层推理的魔法。等待期间用户切后台或取消，就取消等待；等待完成后再检查前台、授权及任务状态，不复用几秒前的判断。

### 常见误区
1. 很多人以为“最多重试2次”等于总尝试2次；其实首次加2次会执行3次。变量必须叫已开始次数，计数在执行开始前增加，失败后不归零。
2. 很多人以为BUSY就是临时繁忙；其实官方把不同原因合在9里。只有状态与正延迟都明确才候选放行，靠消息包含busy不可靠。
3. 很多人以为超时后点击“重试”不影响旧调用；其实结束未知时第二次执行可能并存。未知状态先停止，不用新请求ID绕开在途锁。

## 2 代码片段（40 min）
- **场景**：为Android摘要按钮先定义可单测的重试决策；这里是纯策略，不调用模型。
- **依赖与版本**：Python 3.9.6；`math`、`dataclasses`均为该版本标准库，无pip包、无SDK。源码约50行，固定fixture。
- **最小可运行代码**：保存为`retry_budget.py`，运行`python3 retry_budget.py`。
```python
import math
from dataclasses import dataclass, replace

@dataclass(frozen=True)
class Failure:
    code: int = 9
    foreground: bool = True
    finished: bool = True
    released: bool = True
    partial: bool = False
    allowed: bool = True
    retry_ms: float = 1234.1
    attempts: int = 1  # 已开始次数，包括首次
    elapsed_ms: int = 100  # 首次受理以来的等待与操作

# 应用建议值，不是SDK默认；预算单位统一为毫秒
MAX_ATTEMPTS, TOTAL_MS, OP_CAP_MS = 2, 2500, 900

def decide(f):
    if f.code != 9:
        return 'STOP', 0  # policy、取消、未知均拒绝
    if not all(x is True for x in
               (f.foreground, f.finished, f.released, f.allowed)):
        return 'STOP', 0
    if f.partial is not False:
        return 'STOP', 0
    d = f.retry_ms
    if (type(d) not in (int, float) or not math.isfinite(d) or d <= 0):
        return 'STOP', 0
    wait_ms = math.ceil(d)  # 不可向下取整压短服务建议
    if (type(f.attempts) is not int or not 1 <= f.attempts < MAX_ATTEMPTS
            or type(f.elapsed_ms) is not int or f.elapsed_ms < 0
            or f.elapsed_ms + wait_ms + OP_CAP_MS > TOTAL_MS):
        return 'STOP', 0
    return 'RETRY', wait_ms

base = Failure()
assert decide(base) == ('RETRY', 1235)
fixtures = [dict(code=c) for c in (4, 11, 15, 7, 999)]
fixtures += [dict(foreground=False), dict(finished=False),
             dict(released=False), dict(partial=True), dict(allowed=False),
             dict(retry_ms=0), dict(retry_ms=-1), dict(retry_ms=float('nan')),
             dict(attempts=2), dict(elapsed_ms=500)]
for change in fixtures:
    assert decide(replace(base, **change)) == ('STOP', 0), change
print('EXECUTED_HOST: 16 assertions passed; retry_wait_ms=1235')
print('固定fixture；SDK/设备/模型/性能/usage均未测量')
```

```text

固定fixture；SDK/设备/模型/性能/usage均未测量
```
- **逐行要点**：冻结Failure避免判定期间字段被改；`is True`要求明确肯定，None不是肯定；`partial is not False`拒绝未知；先校验有限正延迟再ceil；最后同时检查总次数与时间，而不是只看delay。
- **踩坑提示**：这段代码只返回计划，不真的等待、不发起请求、不确认设备释放。不要把16项通过写成Nano稳定性或性能实测。接入层必须维护单调时钟、执行前二次校验和取消传播；业务拒绝不能通过修改`allowed`为真绕过。代码里的浮点毫秒仅为演示向上取整，SDK Duration应保持精度后换算，不先截断小数。
