## 1 概念精讲（30 min）
- 一句话定义：**只读对账**是围绕同一个已登记操作，读取后端状态并核验证据，再决定是否允许本地账本结束占位；它不是再次执行任务。
- 它解决什么问题 / 为什么现在必须懂：昨日已把UNKNOWN保存到磁盘，但重启后的UI还需要回答“旧任务有没有结束”。超时后再POST、改ID或切后端都可能产生第二次执行；今天练的是给旧操作查状态，而不是重新提交一份Prompt。
- 关键机制（教学契约，不是未知SDK的现成功能）：

```text
昨日持久UNKNOWN → SELECT读取原(op_id, account, digest, backend)
    ↓ 已批准的只读契约 + 同完整身份的查询scope？
  否 → NOT_EXECUTED，保留UNKNOWN，不发查询
  是 → 查询预算还有余量？
         否 → 待确认，保留UNKNOWN，不自动补预算/重发
         是 → 扣一次查询预算 → 只访问旧操作的状态（本课仅本地stub）
                ↓ 超时 / 404 / 未知 / 运行中 / 身份错 / 证据缺失
              待确认，保留UNKNOWN，不创建新生成
                ↓ 可信adapter核验同身份 + 终结 + 资源释放
              交昨日finish → 提交成功才 TERMINAL、释放占位
                ↓ 仅状态更新；没有自动生成、换ID、切云或复活旧ID
```

  1. **先批准，再查询**：批准包含后端/环境、操作身份作用域与只读接口契约。不能凭URL长得像 `/status` 就认为安全；查询只携带必要操作身份，不重传Prompt明文。生产授权来源和服务支持需明确，本课只模拟已批准fixture；真实契约/scope尚未确认，真实查询 `NOT_EXECUTED`。
  2. **查询失败不能当任务不存在**：404可能涉及错误环境、权限隐藏、保留期等，本课不归因、更不据此清UNKNOWN；“没有找到证据”不是“证明没有执行”。查询超时也不能拿生成重试来补救。
  3. **查询预算与生成预算分离**：本课预算最多2次查询，失败也扣减；耗尽显示“旧任务待确认，查询预算耗尽”，不再轮询、不清占位。2次是教学参数，不是厂商限制。预算这里只在对象内存中，不是跨重启的生产预算；不允许借重建对象自动续查。
  4. **响应不是验证器**：回包写 `trusted=true`、`done=true` 或“成功”都不够；adapter必须关联全部四个身份，确认终结和实际资源释放，然后才能调用昨日的 `finish`。释放不能从无来源的布尔值猜出。
- 来源边界：Google官方协议的 `GetOperation` 读取长操作最新状态，`name` 只在原服务内唯一，`done` 表示完成，但**没有通用资源释放证明字段**；这里只用于解释查询模式，不声称DHwork或ML Kit支持该协议。[S04 协议源码](https://raw.githubusercontent.com/googleapis/googleapis/master/google/longrunning/operations.proto)。HTTP GET的安全方法语义是“不请求改变状态”，不保证对端实现无实际副作用；仍需批准业务契约和scope。[S05 RFC 9110 §9.2.1](https://www.rfc-editor.org/rfc/rfc9110.html)。
- 常见误区：
  - 很多人以为“GET天然没副作用，直接查一下没事”，其实方法名不认证对端实现，也不授予账号/隐私scope；未批准就NOT_EXECUTED。
  - 很多人以为“404、超时或预算耗尽说明旧操作可以清掉”，其实只是查询没有证实终结与释放，UNKNOWN必须保留。
  - 很多人以为“trusted=true是可信证据”，其实可信adapter必须独立验证；本课对象白名单与trusted都是fixture，不是真签名、认证或释放证明。

```python
"""只读查询Host夹具：零网络，trusted不是认证，绝不创建生成。"""
import sqlite3
from ledger_host import valid

class Budget:
    def __init__(self, remaining):
        if type(remaining) is not int or remaining < 0:
            raise ValueError('查询预算必须是非负整数')
        self.remaining = remaining

    def take(self):
        if self.remaining == 0:
            return False
        self.remaining -= 1  # 查询失败也消耗预算；绝不是生成重试预算。
        return True

class QueryStub:
    def __init__(self, replies):
        self.replies, self.calls = list(replies), []

    def query(self, identity):
        self.calls.append(identity)  # 仅记内存日志，没有HTTP或生成接口。
        reply = self.replies.pop(0)
        if isinstance(reply, Exception):
            raise reply
        return reply

class FixtureAdapter:
    def __init__(self, *, contract=False, scope=None, receipt=None):
        self.contract, self.scope, self.receipt = contract, scope, receipt

    def approved(self, identity):
        return self.contract is True and valid(self.scope) and self.scope == identity

    def verify(self, reply, identity):
        # 对象白名单仅模拟独立验证器；JSON里trusted=True不能自行成为证据。
        # 生产必须由已批准adapter验证来源/账号/后端代际/关联/终结与释放。
        return (reply is self.receipt and isinstance(reply, dict)
                and type(reply.get('http')) is int and reply['http'] == 200
                and valid(reply.get('identity')) and reply['identity'] == identity
                and all(reply.get(k) is True for k in ('trusted', 'terminal', 'released')))

def reconcile(ledger, adapter, stub, budget):
    if ledger.c is None:
        return '待确认：账本不可读'
    try:
        row = ledger.c.execute(
            'SELECT op_id,account,digest,backend FROM ops WHERE slot=1').fetchone()
    except sqlite3.Error:
        return '待确认：账本不可读'
    if row is None:
        return '无待确认操作（不创建新生成）'
    identity = tuple(row)  # 只从旧占位恢复完整身份，不接收替换ID。
    if not valid(identity) or not adapter.approved(identity):
        return 'NOT_EXECUTED：契约或查询scope未批准'
    if not budget.take():
        return '待确认：查询预算耗尽'
    try:
        reply = stub.query(identity)
        if not adapter.verify(reply, identity):
            return '待确认：状态或证据不充分'
        # 只有经adapter验证的同身份终结+释放才能交给昨日finish。
        ok = ledger.finish(identity, trusted=True, terminal=True, released=True)
        return '已对账：终结并释放' if ok else '待确认：账本提交未成功'
    except Exception:
        return '待确认：查询或验证失败'  # 404/超时/未知绝不删UNKNOWN或重发。

if __name__ == '__main__':
    from pathlib import Path
    from tempfile import TemporaryDirectory
    from ledger_host import Ledger, bootstrap_fixture
    with TemporaryDirectory() as d:
        p = Path(d) / 'fixture.db'; bootstrap_fixture(p)
        identity = ('op-1', 'account-A', 'sha256:fixture', 'backend-A:generation-1')
        ledger = Ledger(p); assert ledger.reserve(identity)  # 人工造占位，无生成。
        reply = dict(http=200, identity=identity, trusted=True, terminal=True, released=True)
        adapter = FixtureAdapter(contract=True, scope=identity, receipt=reply)
        stub, budget = QueryStub([{'http': 404}, reply]), Budget(2)
        print(reconcile(ledger, adapter, stub, budget))
        print(reconcile(ledger, adapter, stub, budget))
        print('查询次数:', len(stub.calls), '剩余预算:', budget.remaining)
        print('账本:', ledger.c.execute('SELECT state,slot FROM ops').fetchone())
        print('usage=NOT_EXECUTED（无模型调用）'); ledger.close()
```

- 逐行要点：
  - `SELECT ... WHERE slot=1`：从原占位读取完整身份，没有调用 `submit`、生成接口或清库；新ID根本不是查询参数。
  - `adapter.approved(identity)`：契约严格True且scope与四字段原身份一致，门禁失败不调用stub、不扣预算。
  - `budget.take()`：先扣查询预算再尝试；失败也计费于本地查询次数，耗尽继续保留占位。不是模型usage。
  - `reply is self.receipt` + 严格True：用fixture白名单模拟验证器边界，普通JSON自报trusted不能过；真实认证、签名、证据时效、后端代际验证未实现。
  - `ledger.finish(...)`：唯一写入点，只有adapter验证通过后才进入昨日原子结束逻辑；提交失败仍待确认，不自动新生成。
- 踩坑提示：
  - fixture批准和对象白名单**不等于真实批准/认证**。生产不能让查询响应自己决定可信、终结或释放；实际adapter须由后端契约与安全评审批准，本课未实现，真实操作查询NOT_EXECUTED。
  - 不要把官方长操作的 `done` 直接映射到 `released=True`；完成、结果是否保留、资源是否释放是不同契约。本课释放标记是人工fixture，没有远端实测。
  - 查询预算是内存教学对象；重启/重建对象可重置数值，不能把它当已验证的跨进程预算方案。真实轮询、退避、刷新授权、跨进程查询预算均未实现。
  - 今日数据库只在TemporaryDirectory里人工 `reserve` 造UNKNOWN；没有真实发送。测试负例尝试新ID `submit` 都被旧账本挡住，dispatch次数0。不要对昨日文件/线上库运行初始化。
