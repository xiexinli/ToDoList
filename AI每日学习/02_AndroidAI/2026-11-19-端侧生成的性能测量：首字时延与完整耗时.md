## 1 概念精讲（30 min）
- **一句话定义**：性能测量是在**同一单调时钟域**中记录可复核事件，再按明确边界计算差值，而不是“启动一个计时器，最后报毫秒数”。
- **它解决什么问题 / 为什么现在必须懂**：同一个“710ms”可能包括门禁/排队，也可能只包含生成；遇到截断后立即结束更快，却不代表更好。下一步做端云比较或优化，先需要不会误导你的基线。

### 1.1 单调时钟与四个主要观察点
〔S01〕官方`SystemClock.elapsedRealtimeNanos()`：从本次系统启动起算、**单调且包含深睡眠**，API17加入。本课最低API26来自Prompt要求，不是时钟要求。
- 不用`System.currentTimeMillis()`算耗时：墙钟可能被校时/人为修改；日期只能用于运行标签。
- 不混用`uptimeMillis()`：它不计深睡眠；也不跨重启/设备/Host减时间戳。纳秒单位不意味着纳秒准确度。
- 包含睡眠与调度等待是用户等待时间的组成部分，**不是CPU执行时间**；丢前台/系统休眠必须记录环境变化，不能拿来声称模型纯算力。

```text
同设备/同次启动/同一elapsedRealtimeNanos时钟域
请求受理 t_request
  → 应用排队/创建/检查可用性/准备请求（每次实际发生的前置步骤都记条件）
生成收集即将开始 t_generate
  → SDK内部排队/输入处理/首片传递；空串、空白或纯元数据不是有效首字
首个有效正文到达 t_first_body
  → 更多正文增量（相同字合法，不按文本去重）
最终标记帧 t_marker（也可能带正文）
  → collect正常返回 t_end_success
  → UI实际绘制、资源close、日志落盘（另记，不混入以上生成耗时）
任一步中断 → t_observed_end + status；不是t_end_success
```

| 指标 | 计算边界 | 能说明/不能说明什么 |
|---|---|---|
| 请求首字时延 `ttft_request_ms` | `(t_first_body - t_request)/1e6` | 用户受理后的正文可用等待；包含本次前置工作，不含受理前等待 |
| 生成首字时延 `ttft_generation_ms` | `(t_first_body - t_generate)/1e6` | 从开始收集到首个有效正文；不是纯prefill或第一个模型Token时间 |
| 请求完整耗时 `complete_request_ms` | 成功时 `(t_end_success - t_request)/1e6` | 本次请求到正常完成的端到端等待；不含close/实际绘制 |
| 生成完整耗时 `complete_generation_ms` | 成功时 `(t_end_success - t_generate)/1e6` | 应用观测生成专段，仍含SDK排队/传递/调度，不是纯decode |
| 已观察耗时 `observed_*_ms` | `(t_observed_end - 对应起点)/1e6` | 成功或中断时的观察跨度；中断时只作为删失/失败记录 |

**首字定义（本课应用策略）**：首个来自正文字段、包含至少一个非空白字符的片段；`null`、`""`、`" \n"`、只有结束标记都不算。不读取/保存思考过程或把它当正文。只为判定用`strip()/isNotBlank()`，不修改正文；本fixture覆盖空格/制表/换行，不宣称两语言对所有Unicode空白判定完全相同。生产若要统计“第一任意字符”，应另取指标名并固定规则，不能悄悄改口径。

**不是屏幕首字**：`t_first_body`是在收集回调入口立即取的**应用收到正文**时间；真正屏幕出现还要等状态发布与绘制，本课未测`t_ui`。帧到达可能是多个字一组，不等于单Token到达，因此不将该指标包装成引擎TTFT。

### 1.2 完成不是看到STOP；未完成样本不是零毫秒
〔S02/S03/S04/S06〕今天独立实读：Flow每次只有一个候选，中间`finishReason=null`，最后非空；指南明确正文为追加增量。这里仅复核**时间事件含义**，不重写昨日拼接逻辑。
- 每帧入口先取时间，再检查正文；最终帧的正文也能成为首字。两个`"哈"`都合法，不能因重复而忽略后一个事件。
- `STOP`是自然结束原因，不是收集协程“已经无异常返回”的证明；`t_marker`与`t_end_success`分开记录。最终帧之后发生异常仍是异常样本。
- 无首字：`first_ns=null`、两个首字时延也为`null`，**不要填0或超时阈值**。生成尚未开始的门禁拒绝或前置异常/取消/超时：`generation_ns=null`，只有请求观察跨度，不能构造生成指标。
- 异常/取消/超时：观察终点只表示应用收到了中断；**未测设备计算何时真正停止/何时真正释放**。预算10秒不意味着实测完成时长正好10秒，协作取消/调度可能导致观察更晚。

| 观察结果 | 应用状态 | 首字记录 | 完整耗时与统计资格 |
|---|---|---|---|
| collect正常返回 + STOP + 有效正文 | SUCCESS | 有时间 | 写完整耗时；进入同条件成功样本分位数 |
| collect正常返回 + STOP + 无有效正文 | EMPTY_RESULT | null | 完整耗时null；单列失败类别 |
| 正常返回 + MAX_TOKENS，有/无正文 | TRUNCATED | 若已有正文保留 | 完整耗时null；隔离，不能把短截断当快成功 |
| 正常返回但无终标/OTHER/未知原因 | INCOMPLETE | 如有则保留 | 不具备成功凭证，隔离 |
| 异常/外部取消/自身预算超时 | ERROR / CANCELLED / TIMEOUT | 如有则保留 | 只保留观察跨度，失败数单列 |
| 时间倒退、终帧后再来帧、缺边界等 | INVALID | 无可信指标 | 直接隔离，不将负值截成0再统计 |
| 生成前被门禁拒绝 | REJECTED | null | 只有请求观察跨度，生成指标null |

Host表里的状态是应用标签，不是SDK枚举。Kotlin另将丢最上层前台记`ENV_INVALID`。非成功样本的首字可以用于“失败前是否有预览”的诊断表，**不混入成功样本分位数**。

### 1.3 一行记录配一组条件，不能混冷热
以下是**待真机执行的记录规范〔PROPOSAL〕**，本轮未采集设备数据。

| 必记条件 | 记录方法与测量边界 |
|---|---|
| 来源与时钟 | `origin`、设备别名、同启动会话ID、时钟API；Host合成记录独立目录/分组，来源标签本身不证明来自真机 |
| 软件/模型 | Android版本/构建、App版本/构建类型、SDK精确版本、AICore/模型标识（读不到写UNKNOWN，不猜Nano版本） |
| 固定任务 | 虚构输入case_id、输入长度及其单位、请求参数/maxOutputTokens/预算；不保存真实便签或推理链 |
| 冷/暖与缓存 | 客户端新建/复用、是否显式warmup、上次成功生成时间与间隔、相同输入/前缀、运行序号；不同条件拆组 |
| 前台与并发 | 全程最上层前台、是否途中丢前台、同应用是否单飞、其他可观察负载；前台服务不是前台证据 |
| 资源环境 | 可观测的温控/电量/充电/省电/内存条件与采集方法；取不到写NOT_MEASURED，不能默认为正常 |
| 终态与清理 | 请求/生成/首字/终帧/观察终点、结束原因、应用状态、取消来源；close尝试耗时/错误另外记录，不保证释放成功 |

**冷与暖只能按证据命名**：〔S04〕`warmup()`可以加载Nano到内存并初始化运行组件；本次只读文档，未调用。新建`Generation.getClient()`不等于AICore冷启动，重复同提示又可能享受缓存。可以叫“新客户端、未显式预热、模型驻留未知”或“连续调用第2次”，不能无证据标“真冷/真暖”。本课不强杀进程、清缓存或操作手机。

**统计口径**：同设备/模型/任务/参数/预算/冷热/前台/资源条件才可汇总；未知条件用运行ID隔开，不把所有UNKNOWN都当同组。报告总尝试数、各终态数量、成功率和**成功样本**首字/完整耗时的n、p50、p95。算法固定`nearest-rank = 排序后第ceil(n×p)个`，不混用插值或中值平均。
- n=0→分位数与无样本成功率为null；n=1→p50=p95=唯一值，仅描述样本。
- 成功n<20显式提示尾延迟证据不足；n≥20也不自动产生置信度保证。样本小不宣传“p95已稳定”。
- 同时报告失败类别；只看成功p95会产生幸存者偏差。超时是未完成观察，不是“在超时点成功”；本课不展开删失生存分析。
- **tokens/s不计算**：无真实输出Token数，也没有首片Token数与解码边界；字符数/帧数/maxOutputTokens不是已生成Token数。〔S02〕`countTokens(request)`只数输入，不能拿来当输出usage。无Token计数时明确`NOT_MEASURED`，不是造一个字符→Token比例。

**常见误区（3条）**：
1. 很多人以为“第一个流值/第一个Token就是首字”，其实空片、纯结束元数据不是正文，正文到达也不是已经绘制；请固定观察点。
2. 很多人以为“STOP或超时代表完整耗时”，其实STOP后要等正常收集结束，超时/取消只能记观察跨度，不能混入成功分位数。
3. 很多人以为“新客户端就是冷启动，Host测得毫秒就是Nano速度”，其实驻留/缓存未知，合成时间只校验公式，真机条件与执行证据不可替代。

### 2.1 最小可运行程序（EXECUTED_HOST_SYNTHETIC_FIXTURE）
以下与证据目录`latency_meter.py`逐字一致，保存后直接`python3 -B latency_meter.py`。**它是事件统计器，不连接SDK；ns是注入的合成单调值，不是Host读表得到的时间，更不是Nano时间。** 没有fake模型调用来冒充推理。
```python
"""合成单调时序fixture统计器：Host可运行；不是Nano性能实测。"""
import json
import math
from collections import Counter
from dataclasses import dataclass, asdict
from typing import Optional


@dataclass(frozen=True)
class Event:
    kind: str
    ns: int  # 调用者注入同一单调时钟域的纳秒；fixture值纯合成
    text: Optional[str] = None
    reason: Optional[str] = None
    outcome: Optional[str] = None


@dataclass(frozen=True)
class Sample:
    origin: str
    conditions: str
    status: str
    valid: bool
    first_ns: Optional[int] = None
    marker_ns: Optional[int] = None
    ttft_request_ms: Optional[float] = None
    ttft_generation_ms: Optional[float] = None
    observed_request_ms: Optional[float] = None
    observed_generation_ms: Optional[float] = None
    complete_request_ms: Optional[float] = None
    complete_generation_ms: Optional[float] = None
    issue: str = ""


def analyse(events, origin="SYNTHETIC_FIXTURE", conditions="固定条件示例"):
    """NORMAL指collect正常返回，不能只用最后一个finishReason代替它。"""
    def invalid(message):
        return Sample(origin, conditions, "INVALID", False, issue=message)
    if origin not in ("SYNTHETIC_FIXTURE", "ANDROID_ELAPSED_REALTIME_NS"):
        return invalid("未知时钟来源；拒绝墙钟或Host测量混入")
    if (len(events) < 2 or events[0].kind != "request"
            or events[-1].kind != "end"):
        return invalid("缺少请求起点或观察终点")
    if any(type(e.ns) is not int or e.ns < 0 for e in events):
        return invalid("时间必须为非负整数纳秒")
    if any(a.ns > b.ns for a, b in zip(events, events[1:])):
        return invalid("时间倒退；不截成0、不参与分位数")
    request = events[0].ns
    generation = first = marker = reason = None
    for e in events[1:-1]:
        if e.kind == "generation":
            if generation is not None:
                return invalid("重复生成起点")
            generation = e.ns
        elif e.kind == "frame":
            if generation is None or marker is not None:
                return invalid("正文在生成前或终帧后出现")
            if e.text is not None and not isinstance(e.text, str):
                return invalid("正文类型错误")
            if e.reason is not None and not isinstance(e.reason, str):
                return invalid("结束原因类型错误")
            # 空串、null、纯空白不是有效首字；不去重，不记录正文/思考过程。
            if first is None and (e.text or "").strip():
                first = e.ns  # 最终帧的正文也必须检查
            if e.reason is not None:
                marker, reason = e.ns, e.reason
        else:
            return invalid("未知或重复边界事件")
    outcome, end = events[-1].outcome, events[-1].ns
    if outcome not in ("NORMAL", "ERROR", "CANCELLED", "TIMEOUT", "REJECTED"):
        return invalid("未知观察终态")
    if generation is None:
        if outcome == "NORMAL":
            return invalid("未开始生成不能正常完成")
        # 门禁前拒绝/异常/取消/超时都可能出现；只记录请求观察跨度。
        return Sample(origin, conditions, outcome, True,
                      observed_request_ms=(end-request)/1_000_000)
    if outcome == "REJECTED":
        return invalid("生成后不能伪称前置拒绝")
    if outcome != "NORMAL":
        status = outcome  # 即使见过STOP，之后异常/取消/超时也不是成功
    elif reason == "MAX_TOKENS":
        status = "TRUNCATED"
    elif reason != "STOP":
        status = "INCOMPLETE"
    else:
        status = "SUCCESS" if first is not None else "EMPTY_RESULT"
    ms = lambda a, b: None if a is None or b is None else (a-b)/1_000_000
    success = status == "SUCCESS"
    return Sample(origin, conditions, status, True, first, marker,
                  ms(first, request), ms(first, generation),
                  ms(end, request), ms(end, generation),
                  ms(end, request) if success else None,
                  ms(end, generation) if success else None)


def percentile(values, p):
    """nearest-rank；p50也用同一算法，不假装为两中值平均数。"""
    if not 0 < p <= 1:
        raise ValueError("分位点必须在(0,1]")
    if not values:
        return None
    if any(not math.isfinite(v) or v < 0 for v in values):
        raise ValueError("无效时长")
    return sorted(values)[math.ceil(len(values)*p)-1]


def summarize(samples):
    # 必须先按来源和全部条件分组，禁止冷热或合成/真机混合。
    groups = {(s.origin, s.conditions) for s in samples}
    if len(groups) > 1:
        raise ValueError("先按同来源/同条件分组，再统计")
    successful = [s for s in samples if s.valid and s.status == "SUCCESS"]
    metrics = {}
    for key in ("ttft_request_ms", "ttft_generation_ms",
                "complete_request_ms", "complete_generation_ms"):
        values = [getattr(s, key) for s in successful]
        metrics[key] = {"n": len(values), "p50": percentile(values, .5),
                        "p95": percentile(values, .95)}
    n = len(successful)
    return {"group": next(iter(groups), None), "attempts": len(samples),
            "statuses": dict(Counter(s.status for s in samples)),
            "success_rate": n/len(samples) if samples else None,
            "successful_n": n, "metrics": metrics,
            "warning": "无成功样本，分位数为null" if not n else
```

### 2.3 Android仪器接入片段（SPEC_CHECK，NOT_EXECUTED）
以下与`NanoLatencyProbe.kt`逐字一致。**不是独立可运行App**：需要已有工程提供合法请求、已完成门禁的客户端、用户受理时间、最上层前台证据与不抛错的本地记录器。本次不改工程/编译/连手机，所以不宣称Android已运行。

调用方在**请求受理、排队/门禁之前**保存`val requestNs = SystemClock.elapsedRealtimeNanos()`；若此前置步骤拒绝，应单独记录REJECTED而不进入此函数。调用方在外层finally尝试close、独立记录清理结果。函数既不拼正文，也不改Compose生命周期；只在已就绪生成专段打点。
```kotlin
// SPEC_CHECK，NOT_EXECUTED：不是独立App；不含Compose/流式拼接/模型下载。
// com.google.mlkit:genai-prompt:1.0.0-beta4；协程核心1.7.3；Android API>=26。
import android.os.SystemClock
import com.google.mlkit.genai.prompt.Candidate
import com.google.mlkit.genai.prompt.GenerateContentRequest
import com.google.mlkit.genai.prompt.GenerativeModel
import kotlinx.coroutines.CancellationException
import kotlinx.coroutines.currentCoroutineContext
import kotlinx.coroutines.ensureActive
import kotlinx.coroutines.flow.collect
import kotlinx.coroutines.withTimeoutOrNull

data class LatencyRecord(
    val requestNs: Long,
    val generationNs: Long?,
    val firstBodyNs: Long?,
    val finishMarkerNs: Long?,
    val observedEndNs: Long,
    val status: String,
    val clock: String = "ANDROID_ELAPSED_REALTIME_NS"
) // 原始单调时间，不记录正文/提示词/思考过程；统计与分组在测量后做。
private class BadTimeline : Exception()
private class ForegroundLost : Exception()

suspend fun measureReadyStream(
    model: GenerativeModel, // 调用方已做门禁，拥有客户端并在外层finally尝试close
    request: GenerateContentRequest, // 已构建；candidateCount=1
    requestNs: Long, // 用户请求受理时的elapsedRealtimeNanos；在排队/门禁之前
    budgetMs: Long,
    isTopForeground: () -> Boolean, // 实际最上层前台证据，不是前台服务
    report: (LatencyRecord) -> Unit // 必须不抛错/不挂起；本地收下记录，稍后写文件
) {
    require(budgetMs > 0L) // 预算与条件一起登记，不能只保留跑得完的样本
    var generation: Long? = null
    var first: Long? = null
    var marker: Long? = null
    var reason: Int? = null
    var last = requestNs
    var end: Long? = null
    var status = "ERROR"
    fun stamp(): Long {
        val now = SystemClock.elapsedRealtimeNanos()
        if (requestNs < 0L || now < last) throw BadTimeline()
        last = now
        return now
    }
    try {
        currentCoroutineContext().ensureActive()
        if (!isTopForeground()) throw ForegroundLost()
        val completed = withTimeoutOrNull(budgetMs) {
            generation = stamp() // 即将开始collect；不是只测创建冷Flow对象
            model.generateContentStream(request).collect { response ->
                val arrival = stamp() // 第一行取时间：在检查/记录/渲染之前
                currentCoroutineContext().ensureActive()
                if (!isTopForeground()) throw ForegroundLost()
                if (marker != null) throw BadTimeline() // 标记后再来帧：契约异常
                val candidate = response.candidates.singleOrNull() ?: throw BadTimeline()
                if (first == null && candidate.text.orEmpty().isNotBlank()) first = arrival
                // 最终帧先查正文，不能只看结束原因；不读取推理过程。
                reason = candidate.finishReason
                if (reason != null) marker = arrival
            }
            end = stamp() // collect正常返回的时刻；不同于STOP到达
            true
        }
        currentCoroutineContext().ensureActive()
        if (!isTopForeground()) throw ForegroundLost()
        if (completed == null) {
            end = stamp(); status = "TIMEOUT" // 自己预算超时，非完整耗时
        } else {
            status = when (reason) {
                Candidate.FinishReason.STOP -> if (first != null) "SUCCESS" else "EMPTY_RESULT"
                Candidate.FinishReason.MAX_TOKENS -> "TRUNCATED"
                else -> "INCOMPLETE"
            }
        }
    } catch (cancelled: CancellationException) {
        end = SystemClock.elapsedRealtimeNanos(); status = "CANCELLED"
        throw cancelled // 外部取消（含外层超时）继续传播；原因由调用方另记
    } catch (_: ForegroundLost) {
        end = SystemClock.elapsedRealtimeNanos(); status = "ENV_INVALID"
    } catch (_: BadTimeline) {
        end = SystemClock.elapsedRealtimeNanos(); status = "INVALID"
    } catch (_: Exception) {
        end = SystemClock.elapsedRealtimeNanos(); status = "ERROR"
    } finally {
        report(LatencyRecord(requestNs, generation, first, marker,
            end ?: SystemClock.elapsedRealtimeNanos(), status))
        // report之后由外层记录close耗时/错误；不将释放时间混入生成完成时长。
    }
}
```

**逐行要点（5条）**：
1. `requestNs`由受理入口传入；`generation=stamp()`在即将collect处。把门禁之后的时间当请求起点会漏掉用户前置等待。
2. 收集块第一行取`arrival`，再检查正文；时间不取在打印、UI绘制或日志之后。多个字同片，只知道正文片到达，不知道各Token时间。
3. 最终帧也先检查正文，`marker`另存；正常返回才填正常结束时间。没有首字保留null，不补0。
4. `withTimeoutOrNull`吸收自身预算超时；外部取消继续重抛，调用方另记原因（比如外层超时）。不会为了统计把取消转成SUCCESS。
5. `report()`和外层close在测量终点之后，原始记录再交Host校验/分组。`INVALID/ENV_INVALID`不参与成功统计，异常捕获终点也需校验同一时钟与顺序。

**踩坑提示**：
- 回调入口打点仍是应用观察时间，SDK内部线程排队/传递不可见；仪器片段不提供纯prefill/decode拆分，也不承诺不会增加微小探针开销。
- `report`必须不抛错/不挂起；本地收下后再写文件，否则会掩盖原取消。不要在流内记录原始提示/正文/思考过程。
- 预算、前台变化、close错误都保留；不因采集失败只保存快样本。`LatencyRecord.clock`只是声明，必须附同设备运行日志才可称真机证据；Host不能改标签伪装。
- 本Host例只解释事件与分组：真实Android记录接入时要显式转换字段/SDK整数结束原因；当前未实现Android→JSON文件导出，不声称已打通完整真机采集链。
- 本统计器的非成功首字留作诊断；成功表过滤失败。资源/冷热条件签名由记录规范生成，真实运行不得省略设备/模型/任务条件后沿用“固定条件示例”。
