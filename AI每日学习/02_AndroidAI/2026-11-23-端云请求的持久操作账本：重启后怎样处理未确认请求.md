## 1 概念精讲（30 min）
- 一句话定义：**持久操作账本**是把“哪一个操作可能还在后端运行、因而不准再发”保存到磁盘，并让发送资格服从已提交记录的机制。
- 它解决什么问题 / 为什么现在必须懂：昨日的内存 UNKNOWN 能挡住当前进程，却会随 Android 进程回收消失。若云端已经接受请求，客户端重启后把空内存误当“没发过”，换个 ID 或改走另一个后端都会产生第二次执行；UI 消失并不能证明后端释放。
- 关键机制（本讲为单全局占位的保守教学设计，不是SDK契约）：

```text
显式新操作 → BEGIN IMMEDIATE → 检查占位/旧ID → 写 UNKNOWN + slot=1
                  ↓ SQL失败/COMMIT失败：不dispatch
              COMMIT成功 → dispatch fixture
                  ↓ 进程退出、发送异常、回包丢失
              重开原数据库 → 保留 UNKNOWN → 同ID/新ID/换后端都挡住
                  ↓ 只读对账拿到可验证证据（本课未接入）
              同完整身份 + 可信终结 + 确认释放
                  ↓ 同一事务更新 TERMINAL + slot=NULL，COMMIT成功
              允许用户显式创建新操作；不自动发送，也不复活旧ID
```

  1. **先持久占位，再产生外部效果**：`COMMIT` 成功返回才调用 dispatch。占位就先写 UNKNOWN，故崩溃发生在提交后、发送前也宁可误拦，不能推断“绝对没发送”。
  2. **恢复身份必须完整**：教学元组为 `(op_id, account, digest, backend)`。`digest` 代表操作输入的稳定指纹，`backend` 含后端实例/代际标识；只持有相同 ID 不够。测试值是假指纹，生产应从规范化输入计算摘要，别把明文 Prompt 或凭据写进账本。
  3. **恢复不是重试**：普通启动只用 `mode=rw` 打开原库；库丢失、损坏或结构不兼容时失败关闭。只有全新隔离的教学 fixture 才显式 bootstrap；恢复时绝不调用初始化。
  4. **终结与释放不可拆开提交**：同操作的可信结束证据、释放证据都满足才原子更新。提交失败继续占位；旧记录保留，防止终结后的同 ID 再次发送。
- 来源边界：SQLite 原子提交指**数据库事务内部全有或全无**，[S01 官方原理](https://www.sqlite.org/atomiccommit.html)；它不把远端请求变成同一个数据库事务。Python 的 `mode=rw`、显式提交与关闭行为见 [S02 标准库文档](https://docs.python.org/3.9/library/sqlite3.html)（当前在线页面为 3.9.25 文档，代码实跑环境为 3.9.6）。
- 常见误区：
  - 很多人以为“有 SQLite 事务就能跨进程 exactly-once”，其实事务不能证明远端是否接收或完成；此模型只建立保守发送门禁，仍需真实后端幂等与只读对账契约。
  - 很多人以为“重启后用新 UUID 就安全”，其实新 ID 绕不过旧 UNKNOWN 的全局占位；换账号/后端也不能拿来绕过。
  - 很多人以为“库坏了重建空库、收到任意成功回包就解锁”，其实这两种做法都抹去未知操作；数据库异常应关闭发送，回执还必须证明同身份终结且资源已释放。

- 场景：Android AI 摘要任务发到端侧/云端后，应用被回收；下次打开不能对未确认旧操作自动再发。以下把危险窗口缩成可在 Host 上验证的磁盘状态模型。

- 最小可运行代码：保存为 `ledger_host.py`。101 行；完整实测副本与 109 行测试脚本在当天验证目录，不是 Android 实现。

```python
"""仅Host fixture：单全局占位；不联网、不认证、不保证跨进程exactly-once。"""
import sqlite3
from pathlib import Path

SCHEMA = """CREATE TABLE ops (
 op_id TEXT PRIMARY KEY NOT NULL, account TEXT NOT NULL,
 digest TEXT NOT NULL, backend TEXT NOT NULL,
 state TEXT NOT NULL CHECK(state IN ('UNKNOWN','TERMINAL')),
 slot INTEGER UNIQUE,
 CHECK((state='UNKNOWN' AND slot IS NOT NULL AND slot=1) OR (state='TERMINAL' AND slot IS NULL)))"""

def connect(path):
    # rw不创建：丢库、换错路径不能当作“没有任务”。
    c = sqlite3.connect(Path(path).resolve().as_uri() + '?mode=rw',
                        uri=True, isolation_level=None, timeout=0.2)
    try:
        c.execute('PRAGMA synchronous=FULL')
        if c.execute('PRAGMA quick_check').fetchone() != ('ok',):
            raise ValueError('数据库损坏')
        if c.execute("SELECT sql FROM sqlite_master WHERE name='ops'").fetchone() != (SCHEMA,):
            raise ValueError('账本结构缺失或不兼容')
        return c
    except Exception:
        c.close()
        raise

def bootstrap_fixture(path):
    # 仅全新教学fixture显式初始化；恢复路径绝不调用它。
    with Path(path).open('xb'):
        pass
    c = sqlite3.connect(str(path))
    try:
        c.execute(SCHEMA)
        c.commit()
    finally:
        c.close()

def valid(identity):
    return isinstance(identity, tuple) and len(identity) == 4 and all(
        isinstance(x, str) and x for x in identity)

class Ledger:
    def __init__(self, path):
        self.c = None
        try:
            self.c = connect(path)
        except (OSError, ValueError, sqlite3.Error):
            pass  # 失败关闭；不能自动修复、删库或创建空库。

    def close(self):
        if self.c is not None:
            self.c.close()
            self.c = None

    def rollback(self):
        try:
            self.c.execute('ROLLBACK')
        except sqlite3.Error:
            self.close()  # 回滚也失败时关闭，之后全部拒绝。

    def reserve(self, identity):
        if self.c is None or not valid(identity):
            return False
        try:
            self.c.execute('BEGIN IMMEDIATE')
            if self.c.execute('SELECT 1 FROM ops WHERE slot=1').fetchone():
                self.c.execute('ROLLBACK')
                return False
            self.c.execute('INSERT INTO ops VALUES (?,?,?,?,?,?)',
                           (*identity, 'UNKNOWN', 1))
            self.c.execute('COMMIT')  # 必须成功返回后才可dispatch。
            return True
        except sqlite3.Error:
            self.rollback()
            return False

    def submit(self, identity, dispatch):
        if not self.reserve(identity):
            return 'BLOCKED'
        try:
            dispatch(identity)  # 此时库中已保守占位；成功返回也不代表释放。
            return 'DISPATCHED'
        except Exception:
            return 'UNKNOWN'  # 不重发、不清占位。

    def finish(self, identity, *, trusted=False, terminal=False, released=False):
        # trusted只是测试夹具输入，不是签名、TLS或真实后端认证。
        if self.c is None or not valid(identity) or not all(
                x is True for x in (trusted, terminal, released)):
            return False
        try:
            self.c.execute('BEGIN IMMEDIATE')
            changed = self.c.execute(
                "UPDATE ops SET state='TERMINAL',slot=NULL WHERE op_id=? "
                "AND account=? AND digest=? AND backend=? AND slot=1",
                identity).rowcount
            self.c.execute('COMMIT')  # 终结与释放同一事务，失败不能解锁。
            return changed == 1
        except sqlite3.Error:
            self.rollback()
            return False
```

- 逐行要点（只看关键处）：
  - `slot INTEGER UNIQUE` + CHECK：UNKNOWN 必须持有唯一全局占位，TERMINAL 必须没有占位；这是故意比按账号并行更保守的教学范围。
  - `connect(... '?mode=rw', isolation_level=None)`：不偷偷创建丢失账本，关闭隐式事务后明确 `BEGIN / COMMIT / ROLLBACK`；`quick_check` 与结构检查失败就停。
  - `reserve → COMMIT → dispatch`：成功持久化是发送的前置条件；发送返回也仍为 UNKNOWN，不因函数返回就认定资源释放。
  - `finish(... identity ...)`：按全部四个身份字段更新，终结和释放同一事务；`trusted/terminal/released` 必须严格为 `True`。
  - `op_id PRIMARY KEY`：已终结旧 ID 也不能复用。正确回执只解锁，不调用 dispatch；之后的新操作必须显式 submit。
- 踩坑提示：
  - `trusted=True` **只是 fixture 输入，不是认证**。不要把服务端任意 JSON 布尔值当签名验证；实际验证账号、后端身份、回执关联与资源释放未实现、NOT_EXECUTED。
  - 不要捕获数据库错误后继续发送，不要恢复时删库/建表，不要一看超时就清 UNKNOWN。SQL 授权拒绝、COMMIT 授权拒绝都在测试里验证了“不 dispatch”；终结提交失败也未解锁。
  - 本机 Python 3.9.6 的测试钩子用 `set_authorizer(None)` 不能正确清除，首轮有 2 项测试夹具错误；改为始终返回 `SQLITE_OK` 的回调后局部重跑通过。正式业务代码未使用授权钩子。
  - 真实磁盘掉电、逻辑回滚/旧备份、恶意删改库、并发进程竞争、Android 数据迁移与备份恢复未测试；`synchronous=FULL` 不等于验证过存储硬件。不能把 Host 结果叫跨进程 exactly-once。

## 5 明日预告与待复习（8 min）
