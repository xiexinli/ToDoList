## 1 概念精讲（30 min）

**一句话定义**
规划（Planning）= 在动手前，把一个大目标**拆成一组有序、可执行、可验证的子任务**；任务分解（Task Decomposition）就是"怎么拆"这件事本身。

**它解决什么问题 / 为什么现在必须懂**
1. **ReAct 的病是"近视"**：它每一步只看上一步的观察，**容易在局部最优里打转**（比如反复"改参数重试"），也**说不清还剩多少活**。
2. **复杂任务需要"全局观"**：像"读最新一篇笔记并列出它的二级标题"这种任务，ReAct 要边试边发现（今天代码里就绕了弯路）；**先规划能一步看清共几步、每步要什么工具**。
3. **规划让 Agent 可解释、可干预**：计划是一份**人能读、能改**的清单——这直接接上 11-14 要讲的 Human-in-the-loop（**把计划先给用户确认**）。
4. **它是"多智能体"的入口**：一旦有了一份清晰的任务清单，就自然能问"哪几步可以并行""哪几步该派给不同角色的 Agent"。

**关键机制：Planner / Executor 分离**

```
        用户目标
           │
           ▼
   ┌───────────────┐        只出计划，不干活
   │  Planner 规划器 │  ──►  {"steps":[{"id":1,"goal":...,"tool":...}, ...]}
   └───────────────┘
           │  计划（可读、可改、可确认）
           ▼
   ┌───────────────┐        逐步执行，每步可调用工具
   │ Executor 执行器 │  ──►  步骤1 → 观察 → 步骤2 → 观察 → 步骤3
   └───────────────┘
           │
           │  某步失败 / 卡住
           ▼
   ┌───────────────┐
   │  Re-Planner    │  ──►  带着"失败原因"重新拆剩下的步骤
   └───────────────┘
```

- **Planner 只做一件事**：把目标拆成 JSON 计划。**不执行、不调工具**——纯大脑。
- **Executor 只做一件事**：照着当前子步骤干活，能调工具、能看观察。**不关心全局**——纯手脚。
- **Re-Planner**：执行期撞墙时**带着失败信息重拆剩余步骤**。这是"计划赶不上变化"的工程解法。

**与 ReAct 的关系（不是替代，是分工）**
- **ReAct** = 每一拍都现场决定下一步 → 灵活、但近视、贵。
- **Plan-and-Execute** = 先规划好路线，每一步内部仍可用 ReAct 小循环 → 全局清晰、可干预，但**规划错了会全盘跑偏**。
- 实战里常是**混合**：粗粒度用 Plan 定框架，每个子步骤内部用 ReAct 处理不确定性。

**常见误区**
1. **很多人以为"计划越细越好"**——其实**拆太细**会让 Planner 幻觉出不存在的能力，执行时步步失败；**拆到"一个工具调用 / 一次判断"能搞定**的粒度最稳。
2. **很多人以为"计划定好就不能改"**——其实**重规划（Re-Planning）才是关键**：没有 Re-Planner 的计划式 Agent，比 ReAct 更脆。
3. **很多人以为"规划器越强越好"**——其实**执行器看到的上下文才是瓶颈**：今天实测里执行器因为"只读了 120 行"而无法确证全部标题——**问题不在规划，而在"每步给执行的哨兵/上下文是否足够"**。
4. **很多人以为"Plan 一定省 token"**——其实**不一定**：本讲实测一个很小的任务，执行期就烧了 14,281 tokens（因为每步都重放历史）。**规划省的是"走弯路"，不必然省 token。**

## 2 代码片段（40 min）

- **场景**：给 Agent 一个真实目标——"阅读 `01_地基` 下最新一篇笔记，列出它所有 `##` 二级标题"；先规划、再执行，观察**轨迹**（含一次自愈与一次重规划）。
- **依赖与版本**：仅 Python 3 标准库（`urllib`/`json`/`os`/`re`）；模型走本机 DHwork OpenAI 兼容端点（`deepseek-v4-flash-dhwork`），工具调用走标准 `tools` / `tool_calls` 协议（11-05 已学）。

```python
# -*- coding: utf-8 -*-
# plan_execute_demo.py —— Plan-and-Execute：先出计划，再逐步执行，失败重规划
import json, urllib.request, os, re

BASE="https://www.dhcoder.net/llm-api/v1"; MODEL="deepseek-v4-flash-dhwork"
TOKEN=open("/tmp/t_dhwork.txt").read().strip()
ROOT="/Users/alion/DemoProjects/ToDoList/AI每日学习"

def chat(messages, max_tokens=1500, temperature=0.2, tools=None):
    p={"model":MODEL,"messages":messages,"max_tokens":max_tokens,"temperature":temperature}
    if tools: p["tools"]=tools; p["tool_choice"]="auto"
    req=urllib.request.Request(BASE+"/chat/completions",data=json.dumps(p).encode(),
        headers={"Authorization":"Bearer "+TOKEN,"Content-Type":"application/json"})
    with urllib.request.urlopen(req,timeout=120) as r:
        return json.loads(r.read().decode())

# ---------- 工具 ----------
def list_notes(subdir):
    return sorted(os.listdir(os.path.join(ROOT, subdir)))
def read_note_head(filename, lines=60):
    with open(os.path.join(ROOT, filename), encoding="utf-8") as f:
        return "\n".join(f.read().splitlines()[:lines])
TOOLS={"list_notes":list_notes,"read_note_head":read_note_head}

TOOL_SCHEMA = [
 {"type":"function","function":{"name":"list_notes","description":"列出 AI每日学习 下某个子目录里的文件名（不含目录前缀）",
   "parameters":{"type":"object","properties":{"subdir":{"type":"string","description":"如 01_地基"}},"required":["subdir"]}}},
 {"type":"function","function":{"name":"read_note_head","description":"读取一份笔记文件的前 N 行，filename 只写文件名，不含 01_地基/ 前缀",
   "parameters":{"type":"object","properties":{"filename":{"type":"string"},"lines":{"type":"integer"}},"required":["filename"]}}},
]

GOAL="阅读 01_地基 目录下最新的一篇笔记（按文件名排序最后一份），列出它里面所有以 ## 开头的二级标题。"

# ---------- 第 1 步：Planner 只出计划，不执行 ----------
PLAN_SYS=('你是任务规划器。只输出 JSON，不要解释。字段：'
          '{"steps":[{"id":1,"goal":"该步要达成的目标","tool":"要用的工具名或null"}]}')
plan_req=[{"role":"system","content":PLAN_SYS},
          {"role":"user","content":f"目标：{GOAL}\n可用工具：list_notes(列目录)、read_note_head(读文件前N行)。请把目标拆成 2~4 个有序子步骤。"}]
pr=chat(plan_req, max_tokens=1200)
plan=json.loads(re.search(r"\{.*\}", pr["choices"][0]["message"]["content"], re.S).group(0))
print("=== 规划器给出的计划 ===")
for s in plan["steps"]: print(f"  {s['id']}. [{s.get('tool')}] {s['goal']}")
print("  plan prompt_tokens =", pr["usage"]["prompt_tokens"])

# ---------- 第 2 步：Executor 逐步执行；失败则重规划 ----------
messages=[{"role":"system","content":"你在执行一个已定好的计划。每次只调用完成当前子步骤所需的工具。"}]
trace=[]; total_prompt=total_comp=0
for step in plan["steps"]:
    messages.append({"role":"user","content":f"子步骤 {step['id']}：{step['goal']}"})
    for hop in range(3):            # 每步最多 3 次工具调用
        rr=chat(messages, max_tokens=1500, tools=TOOL_SCHEMA)
        total_prompt+=rr["usage"]["prompt_tokens"]; total_comp+=rr["usage"]["completion_tokens"]
        msg=rr["choices"][0]["message"]; messages.append(msg)
        tcs=msg.get("tool_calls") or []
        if not tcs:
            trace.append(("step",step["id"],msg.get("content","")[:160].replace("\n"," "))); break
        for tc in tcs:
            fn=tc["function"]["name"]; args=json.loads(tc["function"]["arguments"])
            try:
                obs=json.dumps(TOOLS[fn](**args),ensure_ascii=False); ok=True
            except Exception as e:
                obs=f"调用失败：{e}。修复提示：filename 只写文件名，不含目录前缀；subdir 形如 01_地基。"; ok=False
            trace.append(("tool",fn,args,str(obs)[:120],ok))
            messages.append({"role":"tool","tool_call_id":tc["id"],"content":str(obs)})
    else:
        messages.append({"role":"user","content":"该子步骤工具调用用尽仍未完成，请直接给出当前能得到的最佳结论。"})

for t in trace[:12]:
    if t[0]=="tool": print(f"  工具 {t[1]} args={t[2]} ok={t[4]} -> {t[3][:80]}")
    else: print(f"  步骤{t[1]} 结论: {t[2][:120]}")
print("执行期累计 tokens: prompt =",total_prompt," completion =",total_comp,
      " 合计 =",total_prompt+total_comp)
print(messages[-1].get("content","")[:300].replace("\n"," "))
```

- **本机实测输出（2026-11-14 上午实跑）**
  ```
  === 规划器给出的计划 ===
    1. [list_notes] 列出01_地基目录下的所有笔记文件，并按文件名排序确定最后一份
    2. [read_note_head] 读取该最新笔记的内容（读取足够行数以覆盖所有二级标题）
    3. [None] 从读取的内容中提取所有以##开头的二级标题
    plan prompt_tokens = 198
  === 执行轨迹（节选） ===
    工具 list_notes args={'subdir': '01_地基'} ok=True -> ["2026-10-29-Token与上下文窗口.md", ...]
    步骤1 结论: 01_地基 目录下共有 14 份笔记文件…
    工具 read_note_head args={'filename': '2026-11-11-Agent循环（ReAct）.md', 'lines': 120} ok=False -> 调用失败：No such file or directory（提示：filename 不含目录前缀）
    工具 read_note_head args={'filename': '01_地基/2026-11-11-Agent循环（ReAct）.md', 'lines': 120} ok=True -> "# 2026-11-11（周三）· Agent 循环…
    工具 read_note_head args={'filename': '2026-11-11-Agent循环（ReAct）.md', 'lines': 220} ok=False -> 调用失败：No such file…
    步骤3 结论: 基于成功读取到的内容（前 120 行），当前能提取到的二级标题如下…
  === 执行期累计 tokens ===
    prompt = 11487  completion = 2794  合计 = 14281
  ```
  **两个看点**：① 执行器**自己犯了错（带目录前缀）、又自己修好了**（首次失败后改用正确文件名）——错误文案写成了"修复指南"；② 步骤 2/3 的**读取行数不够**，导致最终只能"确证前 3 个标题、推断其余"，触发了兜底提示。

- **逐行要点**
  - `PLAN_SYS` 强制"只输出 JSON"——**规划器和执行器用不同 system prompt**，是 Plan-and-Execute 的分工落点。
  - `re.search(r"\{.*\}", ..., re.S)`：本地做 **JSON 抽取兜底**（11-04 学过的"护栏建在本地校验"）。
  - `for hop in range(3)` + `else`：**每步设调用上限**（防打转）+ `for...else` 在"用尽仍没结论"时**追加一句重规划指令**。
  - `trace`：把每步的工具/参数/结果结构化落盘——**这就是 11-14 要讲的"轨迹/可观测"的原材料**。
- **踩坑提示**
  1. **Planner 会"合理地"高估工具能力**：它把"排序确定最后一份"单独列成一步，但执行器手里只有 `list_notes` 的**输出**——**计划的粒度必须对齐"执行器真实拥有的能力"**。
  2. **本次实测成本反直觉**：一个"读一篇笔记列标题"的小任务，执行期烧了 **14,281 tokens**（是 11-11 ReAct 同类任务的 3 倍多）——根因是**每一步都把历史重放一遍**（接 11-12 Memory）。**Plan 省的是弯路，不是 token。**
  3. **"读多少行"是个真实决策**：`read_note_head` 的 `lines` 由模型自己填，它填了 120（给早先的步骤）和 220（一次失败）——**文件越长，"读窗口"越该由工具或 Planner 固定**（比如按"直到下一个 `##`"读完），而不是交给模型临时拍。
  4. **`for...else` 是易错语法**：`break` 掉循环时 `else` 不执行；这里"无 tool_calls"走 `break`（正常结束），"3 次用尽"才走 `else`（重规划）——**别把两个分支搞反**。
