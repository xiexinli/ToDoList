## 1 概念精讲（30 min）

**一句话定义**
结构化输出 = 约束模型产出**符合某个可被程序校验的结构（通常是 JSON Schema）**的结果，使它从"一段人看的文字"变成"一个能给代码用的对象"。

**它解决什么问题 / 为什么现在必须懂**
1. 前三讲我们一直在"跟模型聊天"；从今天起要"**让模型给代码干活**"。代码不吃自然语言。
2. 只要你的 LLM 输出要进数据库、要触发动作、要填表单，**格式错误就是线上故障**——而且它是概率性的、随机出现的故障，最难查。
3. 结构化的能力上限，决定了你能做多复杂的应用：抽取、路由、评分、Agent 的动作参数（明天那一讲）全靠它。

**关键机制：三个层次，能力差一个数量级**

```
层次 1 ── 纯提示词（"请输出 JSON"）
   原理：请求模型照做（它只是"愿意"）
   保证：几乎为零。会带 Markdown 代码围栏、会加解释、会少字段、会说"好的，这是结果："
   适用：一次性脚本、Demo

层次 2 ── JSON 模式（response_format={"type":"json_object"}）
   原理：服务端约束"输出必须是合法 JSON"
   保证：★ 是合法 JSON（能被 json.loads 解析）
        ✗ 不保证字段名、不保证字段齐全、不保证类型
   适用：结构简单、你自己会做二次校验的场景

层次 3 ── 结构化输出（response_format={"type":"json_schema","json_schema":{"strict":true,...}}）
   原理：受约束解码（constrained decoding）——在每个解码步，
        把"违反 schema 的 token"的 logits 置为 -inf，只让合法 token 有概率
   保证：理论上 = 100% 符合 schema
   适用：生产环境、要喂给下游代码的场景
        ⚠️ 但前提是【服务端真的实现了它】——今天就被实测打脸了
```

**受约束解码长什么样**（这是它为什么"理论上"能保证 100% 的原因）：

```
已有文本: {"name": "张
下一个 token 的候选（原始概率）： 三(0.4) 伟(0.2) 好(0.15) }(0.1) ,(0.05) ...
                                ↓ 用 schema 规则屏蔽掉不合法的
合法候选：                       三(0.4) 伟(0.2) 好(0.15) ...  ；"}(0.1)" 被屏蔽
                                （此刻是字符串值的内部，} 是非法的）
重新归一化后采样 ──► 永远不可能生成非法的 JSON
```

> 注意：能屏蔽的前提是**推理端支持**——它在解码循环里拿得到 schema 的语法状态机。很多"OpenAI 兼容"端点只是**收下了参数、透传给上游、然后听天由命**。这就引出今天最重要的实测。

**⚠️ 本机实测：接受 ≠ 强制（2026-11-05 实跑，非杜撰）**

我用**完全相同的 strict schema**、**完全相同的问题**，只改提示词里有没有"只输出JSON"这句，各跑多次：

```
schema: {name: string, age: integer, city: string, 全部 required, additionalProperties: false}

提示词 = "从这句抽取 name/age/city：李四今年30岁，住在上海。"（不提 JSON）
   第1次  合法JSON=False  content='姓名：李四  \n年龄：30岁  \n居住地：上海'
   第2次  合法JSON=False  content='姓名：李四  \n年龄：30岁  \n居住地：上海'
   第3次  合法JSON=False  content='- 李四｜年龄｜30岁  \n- 李四｜居住地｜上海'

提示词 = "...只输出JSON。"（明确要求）
   → 合法JSON=True   content='{"name":"张三","age":18,"city":"杭州"}'
```

**结论：`json_schema` 参数被接受（HTTP 200），但没有做真正的受约束解码**——它只是被当成了一个"建议"。所以在这套端点上，**schema 不能当护栏用，本地校验才是唯一的护栏。**

**常见误区**
1. **"传了 `json_schema` 就万事大吉。"** 今天的实测就是反例。**参数接受 ≠ 约束生效**。正确姿势是三层：提示词明确要求 + 参数声明 schema + **本地校验失败就重试**。
2. **"`json_object` 能保证字段。"** 它只保证"是个合法 JSON"。`{}` 也是合法 JSON。字段名、类型、必填项一概不管。
3. **"schema 可以随便写。"** strict 模式对 schema 有限制：通常要求所有字段都在 `required` 里、`additionalProperties: false`、不支持任意复杂的高阶类型。**"可选字段"要写成 `type: ["string","null"]` 并且仍然放进 required**——这是最常见的踩坑点。
4. **"解析失败就报错给用户。"** 不行。结构化输出天生带**概率性失败**，产品代码里必须内建"校验 → 带上错误信息重试一次 → 再失败才降级"的链路。

## 2 代码片段（40 min）

- **场景**：一个**零依赖**的"抽取 + 校验 + 自动重试"管线。它是本讲的可交付物：把"提示模型输出 JSON"变成"**拿不到合法对象就重试，最终一定返回一个可用对象或明确失败**"。
- **依赖与版本**：**只用 Python 标准库**（3.9+ 可直接运行，本文所有输出由它产出）。生产环境建议再加 `pydantic>=2.7` 做类型校验，思路完全一样。

**① 校验 + 重试管线 `structured.py`**

```python
# structured.py —— 结构化抽取：三层防线（提示词 + schema 参数 + 本地校验重试）
# 零第三方依赖，Python 3.9+ 直接可跑
import json
import os
import re
import urllib.error
import urllib.request
from typing import Any, Dict, Optional, Tuple

URL = "https://www.dhcoder.net/llm-api/v1/chat/completions"
TOKEN = os.environ["DHWORK_TOKEN"]
MODEL = "gpt-5.6-terra-dhwork"

# ---------- schema 定义（注意 strict 模式的三条硬规则） ----------
SCHEMA = {
    "type": "object",
    "properties": {
        "name": {"type": "string"},
        "age": {"type": "integer"},
        # ★ 规则1：想要"可选"，用 type 数组 + null，而不是把它从 required 里拿掉
        "city": {"type": ["string", "null"]},
    },
    # ★ 规则2：strict 模式要求所有字段都在 required 里
    "required": ["name", "age", "city"],
    # ★ 规则3：必须显式关闭额外字段，否则模型会自由发挥
    "additionalProperties": False,
}

RESPONSE_FORMAT = {
    "type": "json_schema",
    "json_schema": {"name": "person", "strict": True, "schema": SCHEMA},
}

# ---------- 极简结构校验器（替代 jsonschema / pydantic 的零依赖版） ----------
_TYPES = {"string": str, "integer": int, "number": (int, float), "boolean": bool}


def _check_type(value: Any, type_spec: Any) -> bool:
    types = type_spec if isinstance(type_spec, list) else [type_spec]
    for t in types:
        if t == "null" and value is None:
            return True
        py = _TYPES.get(t)
        # 注意：Python 里 bool 是 int 的子类，要排除掉避免 True 被当成 1
        if py and isinstance(value, py) and not (t == "integer" and isinstance(value, bool)):
            return True
    return False


def validate(obj: Any, schema: Dict[str, Any]) -> Optional[str]:
    """符合返回 None，不符合返回错误原因（错误原因会喂回模型，帮它自我修正）。"""
    if not isinstance(obj, dict):
        return f"顶层必须是对象，实际是 {type(obj).__name__}"
    props = schema.get("properties", {})
    for key in schema.get("required", []):
        if key not in obj:
            return f"缺少必填字段 '{key}'"
    if schema.get("additionalProperties") is False:
        extra = set(obj) - set(props)
        if extra:
            return f"出现未定义字段: {sorted(extra)}"
    for key, spec in props.items():
        if key in obj and not _check_type(obj[key], spec.get("type")):
            return f"字段 '{key}' 类型应为 {spec.get('type')}，实际是 {type(obj[key]).__name__}"
    return None


# ---------- 模型调用 ----------
def _raw_call(messages, extra: Dict[str, Any]) -> str:
    body = {"model": MODEL, "messages": messages, "max_tokens": 900, **extra}
    req = urllib.request.Request(
        URL, data=json.dumps(body).encode("utf-8"),
        headers={"Content-Type": "application/json", "Authorization": "Bearer " + TOKEN},
    )
    with urllib.request.urlopen(req, timeout=120) as r:
        data = json.loads(r.read().decode("utf-8"))
    return data["choices"][0]["message"].get("content") or ""


def _strip_fence(text: str) -> str:
    """模型很爱加 Markdown 代码围栏（通常带 json 标注），先扒掉再解析。"""
    fence = "`" * 3                                  # 别在字符串里写三个反引号，会截断 Markdown 代码块
    m = re.search(fence + r"(?:json)?\s*(.*?)" + fence, text, re.S)
    return (m.group(1) if m else text).strip()


def extract(text: str, max_retries: int = 2) -> Tuple[Optional[Dict[str, Any]], int]:
    """三层防线在这里落地。返回 (结果, 尝试次数)。"""
    # ★ 第一层：提示词里【必须】明确要求，别指望参数替你干活（今天实测的结论）
    messages = [
        {"role": "system",
         "content": "你是一个信息抽取器。只输出 JSON，不要任何解释、不要 Markdown 围栏。"},
        {"role": "user", "content": f"从下面这句话里抽取 name/age/city：\n{text}"},
    ]
    for attempt in range(max_retries + 1):
        # ★ 第二层：带上 schema 参数（有用，但本机实测不强制）
        try:
            raw = _raw_call(messages, {"response_format": RESPONSE_FORMAT})
        except urllib.error.HTTPError as e:
            # 端点不支持 json_schema 时降级到 json_object —— 不要直接崩
            if e.code == 400 and attempt == 0:
                raw = _raw_call(messages, {"response_format": {"type": "json_object"}})
            else:
                raise

        # ★ 第三层：本地校验，这是唯一能依赖的一层
        try:
            obj = json.loads(_strip_fence(raw))
        except json.JSONDecodeError as e:
            err = f"不是合法 JSON：{e}"
        else:
            err = validate(obj, SCHEMA)
            if err is None:
                return obj, attempt + 1

        # 把失败原因喂回去，让模型自我修正后再试
        messages.append({"role": "assistant", "content": raw})
        messages.append({"role": "user",
                         "content": f"上一次输出不合约：{err}。请重新只输出修正后的 JSON。"})
    return None, max_retries + 1


if __name__ == "__main__":
    samples = [
        "张三今年18岁，住在杭州。",
        "李四今年30岁，住在上海。",
        "王五 22 岁，来自成都。",
    ]
    for s in samples:
        obj, tries = extract(s)
        print(f"输入: {s}\n  -> {obj}  (尝试 {tries} 次)")
```

**本机实测输出（2026-11-05 补写时实跑，非杜撰）**

```
输入: 张三今年18岁，住在杭州。
  -> {'name': '张三', 'age': 18, 'city': '杭州'}  (尝试 1 次)
输入: 李四今年30岁，住在上海。
  -> {'name': '李四', 'age': 30, 'city': '上海'}  (尝试 1 次)
输入: 王五 22 岁，来自成都。
  -> {'name': '王五', 'age': 22, 'city': '成都'}  (尝试 1 次)
```

> 注意：**能一次成功，恰恰是因为第一层的提示词写得足够硬**（"只输出 JSON，不要解释、不要 Markdown 围栏"）。把 system 里那句删掉，就退化成上面实测里 3/3 失败的样子了。

- **逐行要点**
  - `_strip_fence`：**必写**。模型加 ```` ```json ```` 围栏是最常见的"解析失败"原因，而它跟 schema 无关，是提示词习惯问题。
  - `validate` 返回的是**错误字符串而不是 bool**：因为这段文字要**喂回模型**帮它修正。只说"错了"模型改不动，说"缺字段 city"它立刻能补。
  - `isinstance(value, bool)` 那个特判：Python 里 `True == 1`，不做特判的话 `age=True` 会被判成合法的 integer。**这是自己写校验器必踩的坑**。
  - `if e.code == 400 and attempt == 0` 的降级：**参数兼容性要按端点探测**，不是所有"OpenAI 兼容"端点都支持 `json_schema`。
- **踩坑提示**
  1. **strict schema 里"可选字段"要写成 `type: ["string","null"]` 且保留在 `required` 中**——从 `required` 里删掉字段会让严格的 schema 校验器直接拒绝整个 schema。
  2. **别把 schema 的 `description` 当成说明文档写**。它确实会进模型上下文并影响生成，但它是**字段级的提示**，不是放任务规则的地方。
  3. **中文抽取时 enum 里要放中文值**。`{"enum": ["Beijing"]}` 配上中文输入，模型要么返回英文（违反你的预期），要么违反 schema——两边都难受。
  4. **重试要有上限**。`max_retries=2` 是经验值；无限重试会在模型"就是不听话"时把你的钱烧光。

- **与我的工作结合**
  - **Android**：把 `SamplingPreset`（10-31 那讲）+ 结构化抽取组合起来，就是一个"**自然语言控制 App**"的最小内核——用户说"帮我把明天的会议提前半小时"，模型输出 `{"action":"update_calendar","event_id":"...","delta_minutes":-30}`。Kotlin 侧用 `@Serializable data class` + kotlinx.serialization 做同样的"校验失败就重试"，比手写 `JSONObject.optString` 稳得多。

## 5 明日预告与待复习（8 min）

- **明日主题**：Function Calling / 工具调用——W2 收官。让模型不只是"输出结构化数据"，而是"**输出结构化动作**"。
- **待复习（3 条，今天必须记住）**
  1. 结构化输出分三层：**纯提示词 < `json_object` < `json_schema`(strict)**；本机实测 `json_schema` **被接受但不强制**（3/3 次返回自然语言）。
  2. strict schema 三规则：**全字段进 `required`**、**可选字段用 `["string","null"]`**、**`additionalProperties: false`**。
  3. 校验失败要把**具体错误原因**喂回去重试——"缺字段 city"远比"格式错误"有用。
- **一句话复盘**：最容易忘的是——**结构化的护栏必须建在自己的代码里**，参数只是"建议"，端点实现与否不由你决定。
