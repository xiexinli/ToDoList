## 1 概念精讲（30 min）

**一句话定义**
Grounding = 让生成模型**只能依据检索到的片段作答**，并在答案里**标出每句话对应哪条片段**（这就是引用 / Citation）。防幻觉 = 在答案交付前，**逐句核对"这句是否真的被它引用的片段支持"**，不支持的就拦下（改写 / 重生成 / 明确拒答）。

> 一句话记住本质：**RAG 把"闭卷考"变成了"开卷考"，但开卷不等于不会抄错——引用与防幻觉就是那道"阅卷"。**

**它解决什么问题 / 为什么现在必须懂**
1. **RAG 减少幻觉，但不消除**：模型拿到了正确的片段，仍可能**顺着上下文"合理发挥"**——把片段里的"延迟**更高**"写成"延迟**更低**"，或**编一个片段里根本没有的数字**（本讲实测里两条都是真的）。
2. **没有引用 = 无法核对**：用户看到一个笃定的答案，却不知道它**从哪来**，这是企业级场景（法务、医疗、金融、客服）**不能接受**的。
3. **它是 RAG 可信度的最后一道闸**：切片（11-06）→ 向量（11-07）→ 重排（11-08）都是在"**找得对不对**"，只有引用与防幻觉在管"**说得对不对**"。

**关键机制：三道闸，从便宜到贵**

```
检索到的片段 c0/n c1 … ──► LLM 生成答案（每句附 [cX] 标注）
                                   │
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
        ① Prompt 约束（事前）              ② 校验（事后）
        "只依据片段作答；                  a) 本地字面校验：句子与其引用片段的 n-gram 覆盖（便宜，抓不住"否定反转"）
         每句标 [cX]；                         b) 裁判模型：把(陈述, 片段)交给模型判 Supported/Not
         查不到就说不知道"                     c) NLI/专用小模型（如 HHEM）
                    │                             │
                    └──────────────┬──────────────┘
                                   ▼
                        ③ 处置：通过 → 交付（附引用）
                                不通过 → 标注"未找到依据" / 重生成 / 拒答
```

**三条必须记住的**
- **引用是"结构"不是"装饰"**：每句话要能追溯到**具体片段与位置**，才能被核对（所以 11-06 就强调**切片要带元数据**：`source / chunk_index`）。
- **校验有两档，成本差一个数量级**：**字面 n-gram 覆盖**几乎免费但**只能查"有没有提"、查不出"说反了"**；**裁判模型**准但要为每句花一次 LLM 调用。
- **不通过时的"处置"才是工程重点**：是**改答案**、**重生成**，还是**直接告诉用户"没找到依据"**？——**"宁可不答，不可乱答"**是企业级 RAG 的默认姿态。

**常见误区**
1. **"用了 RAG 就不会有幻觉了。"** ✗ RAG 只是把幻觉率**降低**。模型仍会在**拿到正确片段后**犯错（说反、夸大、编数字）。**必须在校验这一层兜底。**
2. **"引用就是把检索到的片段贴到答案末尾。"** ✗ 那样只是"**贴来源**"，不是"**引用**"。真正的引用要求**答案里的每一句都能指回它所依据的那一句/那一段**——**贴一堆来源、却不知道哪句靠哪个**，等于没引。
3. **"校验用字面匹配就够了，省一次 LLM 调用。"** ✗ 本讲实测会给你反例：一条**把"更高"写成"更低"**的幻觉，**字面覆盖率仍然高达 0.429**——**字面校验根本抓不住否定反转**。所以生产上多是"**字面筛一遍做粗滤 → 裁判模型对可疑项精判**"的分层策略。
4. **"校验不过就删掉那句话。"** ✗ 删句会破坏答案连贯、甚至**删掉正确信息**。更好的处置是：**标注"（未找到依据）"+ 交回用户判断**，或**带着"依据不足"的约束重生成**。

## 2 代码片段（40 min）

- **场景**：一条**引用一致性校验**管线。给定"检索片段"和"带引用的答案"，把答案拆成陈述，对每条陈述做**两级校验**：① **本地字面覆盖**（字符 bigram 覆盖，零成本）② **裁判模型**（本机 `deepseek-v4-flash-dhwork`，`temperature=0`，输出 JSON 判定）。用于在 RAG 把答案交给用户前，**把"无据陈述"标出来**。
- **依赖与版本**：`numpy` 可选，本代码只用标准库 `urllib / json / base64 / re`。模型：`deepseek-v4-flash-dhwork`（本机端点实测**接受 `temperature`**，见 11-05 的端点能力实测）。**无需 `openai` SDK。**

**完整代码 `grounding_check.py`**

```python
# grounding_check.py —— 引用一致性校验：逐句检查答案是否被其引用的片段支持
import base64, json, os, urllib.parse, urllib.request

p = os.path.expanduser("~/Library/Application Support/DHwork/config/aionui-config.txt")
d = json.loads(urllib.parse.unquote(base64.b64decode(open(p).read().strip()).decode()))
TOK = d["desktop.bootstrapAuth"]["dhwork"]["accessToken"]
BASE = "https://www.dhcoder.net/llm-api/v1"

def chat(model, messages, **kw):
    payload = {"model": model, "messages": messages}; payload.update(kw)
    req = urllib.request.Request(BASE + "/chat/completions", data=json.dumps(payload).encode(),
        headers={"Authorization": "Bearer " + TOK, "Content-Type": "application/json"})
    return json.load(urllib.request.urlopen(req, timeout=90))

# ① 本地字面校验：陈述的字符 bigram 有多少比例出现在引用片段里（便宜，但抓不住"否定反转"）
def lexical_coverage(claim, ctx):
    grams = {ctx[i:i+2] for i in range(len(ctx) - 1)}
    hit = sum(1 for i in range(len(claim) - 1) if claim[i:i+2] in grams)
    return round(hit / max(1, len(claim) - 1), 3)

# ② 裁判模型：把(引用片段, 陈述)交给模型判"是否被直接支持"，强制输出 JSON
JUDGE_SYS = ("你是严格的『引用一致性』裁判。给定一条陈述和它引用的片段，"
             "只判断片段是否【直接支持】该陈述。只输出 JSON："
             "{\"supported\":true/false,\"reason\":\"≤20字\"}。"
             "片段没提到、或与片段矛盾，都必须判 false。")
def judge(claim, ctx):
    r = chat("deepseek-v4-flash-dhwork",
             [{"role": "system", "content": JUDGE_SYS},
              {"role": "user", "content": f"引用片段：{ctx}\n\n陈述：{claim}"}],
             temperature=0)                      # ★ 判定任务一律 temperature=0
    return r["choices"][0]["message"]["content"].strip()

if __name__ == "__main__":
    CHUNKS = {
        "c0": "重排（Rerank）使用交叉编码器对候选片段逐对打分，通常能提升检索精度，但推理延迟更高、成本更大。",
        "c1": "切片过大会让一个块的向量被平均，检索时变得模糊，召回质量下降。",
    }
    CLAIMS = [                                       # (答案里的一句陈述, 它标注引用的片段)
        ("重排通常能提升检索精度。", "c0"),
        ("重排使用交叉编码器，所以延迟比向量检索更低。", "c0"),
        ("切片过大会导致召回质量下降。", "c1"),
        ("重排可以把端到端延迟降低 90% 以上。", "c0"),
    ]
    for claim, cid in CLAIMS:
        ctx = CHUNKS[cid]
        print(f"陈述：{claim}")
        print(f"  引用 {cid}｜字面覆盖={lexical_coverage(claim, ctx)}｜裁判={judge(claim, ctx)}")
```

**本机实测输出（2026-11-09 实跑，非杜撰）**

```
陈述：重排通常能提升检索精度。
 引用：c0  字面bigram覆盖率=0.818   裁判：{"supported":true,"reason":"片段明确说通常能提升检索精度"}

陈述：重排使用交叉编码器，所以延迟比向量检索更低。
 引用：c0  字面bigram覆盖率=0.429   裁判：{"supported":false,"reason":"片段说延迟更高，陈述相反"}

陈述：切片过大会导致召回质量下降。
 引用：c1  字面bigram覆盖率=0.769   裁判：{"supported":true,"reason":"片段直接说明切片过大导致召回质量下降"}

陈述：重排可以把端到端延迟降低 90% 以上。
 引用：c0  字面bigram覆盖率=0.105   裁判：{"supported":false,"reason":"片段说延迟更高，与陈述相反"}
```

**三处值得停下来想一秒的地方**：
1. **裁判模型两次都抓到了幻觉**：第 2 句（把"延迟**更高**"说成"**更低**"）和第 4 句（**编了"90%"**）都被判 `false`，理由分别是"片段说延迟更高，陈述相反"和"片段说延迟更高，与陈述相反"。**这就是"开卷抄错"被当场抓住。**
2. **字面校验只抓住了其中一条**：第 4 句（编数字）字面覆盖只有 **0.105**，字面校验能发现异常；但第 2 句**字面覆盖高达 0.429**——**字面校验完全看不出问题**，因为它只是把"更高"改成了"更低"，**字面重叠依旧很高**。→ **字面校验抓不住"否定反转 / 说反了"。**
3. **所以生产上要分层**：**字面覆盖先粗筛**（覆盖极低的直接标记为可疑，零成本），**裁判模型再对可疑项精判**（花 token 但准）。**别一上来就对每句都调裁判模型**——那是拿钱和延迟换"用不上的精度"。

- **逐行要点**
  - `lexical_coverage` 用**字符 bigram**：中文没有空格分词，bigram 是最省事的近似。它衡量的是"**字面像不像**"，**不是"意思对不对"**——这就是它抓不住说反了的原因。
  - `JUDGE_SYS` 把判定**约束成 JSON**：便于程序解析。但记住 11-04 讲的——**该端点不强制 JSON**，所以要**本地 `json.loads` + 失败重试**（本例为了简洁直接打印原文，生产要包 `try/except`）。
  - `temperature=0`：**判定任务是确定性任务**，必须关掉随机性。（该端点 `deepseek-v4-flash-dhwork` 接受 `temperature`，见 11-05 实测。）
  - **一条陈述对一条引用**：`CLAIMS` 里每条都带 `[cX]`。**引用不是"贴一堆来源"，而是"每句指回它依据的那一段"**——这正是误区 2 说的区别。
- **踩坑提示**
  1. **字面校验只是粗滤**：`0.429` 这种"看着不低"的幻觉它放过去了。**不要把"字面覆盖高"当成"有据"**。
  2. **裁判模型也会错**：它是另一个 LLM，可能**过度宽松或过度严格**。**不要把它当绝对真理**——它只是"更便宜的人工复核"，重要场景仍需人工抽检。
  3. **成本**：逐句调裁判 = **句数 × 一次 LLM 调用**。答案越长越贵。**先本地粗筛、只对可疑句精判**是常规做法。
  4. **"不支持"的处置要设计**：是标"（未找到依据）"、重生成，还是拒答？**产品上必须先定好策略**，否则校验完了不知道该干嘛。
  5. **引用必须能落到"位置"**：光有 `[c0]` 不够，用户要能看到**具体是哪篇文档的哪一段**——这就是 11-06 强调**切片带元数据**的最终回报。

- **与我的工作结合**
  - **Android（离线问答必须"可溯源"）**：端侧问答若涉及**合规、医疗、金融**，答案**必须带引用**。设计：`assets` 里的知识块带 `source + 序号`（11-06），生成时要求模型每句标 `[chunk_id]`，**交付前做校验**。端侧跑不动裁判模型，可**只用字面粗筛**（免费）**+ 把可疑项打标**，让用户知道"这句依据不足"。**端侧降级策略**：模型能力弱 → 校验放宽，但要**显式提示可信度**。

## 5 明日预告与待复习（8 min）

- **明日主题**：W3 · 第 5 讲（**W3 收官**）—— **RAG 评估（Evaluation）**：怎么用**指标**（召回率 / 命中率 / 引用准确率 / 幻觉率）和**测试集**判断"这套 RAG 到底好不好"，以及怎么用 **badcase 分析**定位问题出在切片、召回、重排还是生成哪一环（正好呼应今天岗位观察里的"评测体系"）。之后进入 **W4「Agent 与工程化」**。
- **待复习（3 条，今天必须记住）**
  1. **RAG 降低幻觉，不消除幻觉**：模型会"开卷抄错"（说反、编数字），**必须在校验层兜底**。
  2. **引用 ≠ 贴来源**：引用的要求是"**答案每句都能指回它依据的那一段**"。
  3. **校验要分层**：**字面覆盖**便宜但抓不住"否定反转"（实测 0.429 仍是通过率很高的假象）；**裁判模型**准但要花 token——**先粗筛、再精判**。
- **一句话复盘**：最容易忘的是——**"校验不过"之后的处置比校验本身更重要**。校验只是"发现问题"，**"宁可不答，不可乱答"的产品策略**才是 RAG 可信度的最终保证。
