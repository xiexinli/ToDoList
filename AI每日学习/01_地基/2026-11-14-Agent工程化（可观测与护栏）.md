## 1 概念精讲（30 min）

**一句话定义**
Agent 工程化 = 在"模型 + 循环"外面，加上**看得见（可观测）、扛得住（可靠性）、管得住（人在回路）**这三层，让 Agent 在真实环境里**可调试、可回滚、可追责**。

**它解决什么问题 / 为什么现在必须懂**
1. **W4 前三讲让你"能跑"，这一讲让你"敢上"**：11-11 的循环、11-12 的记忆、11-13 的计划，都是"能力"；**没有护栏的能力上不了生产**——因为它会花钱、会写数据、会失败、会没人看得懂它干了什么。
2. **Agent 的失败是"静默"的**：它不会崩给你看，它只会**悄悄选错工具、编一个完成、把预算烧光**。你唯一能依赖的就是**轨迹（trace）**。
3. **写操作不可逆**：查数据错了无所谓，**发消息/下单/删文件错了就是事故**——所以"写"必须过一道**审批门**。
4. **这是岗位硬要求**：腾讯 Agent Harness / Agent Infra SRE 等岗位，职责第一条往往就是"**执行轨迹回放、可观测性、SLO/SLI**"——这就是今天这讲。

**关键机制：三道护栏**

```
                    ┌─────────────── 可观测（看得见）───────────────┐
                    │  每个动作落一条结构化 trace：                 │
                    │  {ts, span, step, tool, args, tokens, ms, ok}  │
                    └───────────────────────────────────────────────┘
   用户目标 → [Agent 循环] → 一次工具调用
                    │
                    ├── 可靠性（扛得住）：retry(2, backoff) + timeout + 幂等
                    │                      + 预算刹车(max_steps / max_tokens)
                    │
                    └── Human-in-the-loop（管得住）：
                          risk=="write" 的工具 → 先问人 → 批准才执行
                          未批准 → 返回"已被拒绝"，绝不静默失败、绝不编造
```

- **可观测**：把每一步落成 **JSONL 的 span**——出现问题时**打开日志就是第一现场**（接 11-11 的 `trajectory`、11-13 的 `trace`）。
- **可靠性**：**重试**（瞬时故障）、**超时**（别挂死）、**预算刹车**（`max_steps`/`max_tokens` 硬上限 + 优雅降级）。今天的实测里，一个**模拟的瞬时 IO 故障**就是被 `retry` 救回来的。
- **Human-in-the-loop**：**按风险分级**——读类放行、写类审批；**并且要规定"被拒绝后 Agent 该怎么做"**（提问，而不是编一个"已完成"）。

**常见误区**
1. **很多人以为"能跑通就是工程化"**——其实**能跑通只是 demo**；线上要的是"**出错时你能在 30 秒内知道它错在哪一步、为什么**"，这只有 trace 给得了。
2. **很多人以为"重试总是好的"**——其实**写操作不能无脑重试**（可能重复下单）；重试必须配合**幂等**（同一请求重复执行结果一致）。今天的 `append_line` 演示里就要注意这一点。
3. **很多人以为"人在回路 = 每次操作都弹窗"**——其实那样没人会用它。正确做法是**按风险分级**：读放行、写审批、**高风险二次确认**（接 11-05 的三级权限）。
4. **很多人以为"预算刹车是可选优化"**——其实是**安全阀**：没有 `max_steps`，一个打转的 Agent 会烧穿你的账户；今天代码里 `budget_stop` 那条 trace 就是刹车生效的证据。

## 2 代码片段（40 min）

- **场景**：让 Agent 完成"**把一句话追加到目标文件，再读回来确认**"——一个**带写操作**的真实任务，借此演示三道护栏如何协同工作。
- **依赖与版本**：仅 Python 3 标准库（`urllib`/`json`/`os`/`time`/`re`）；模型走本机 DHwork OpenAI 兼容端点（`deepseek-v4-flash-dhwork`）；工具调用走标准 `tools`/`tool_calls` 协议。

```python
# -*- coding: utf-8 -*-
# agent_ops_demo.py —— Agent 工程化护栏：结构化 Trace + 重试 + HITL 审批 + 预算刹车
import json, urllib.request, os, time

BASE="https://www.dhcoder.net/llm-api/v1"; MODEL="deepseek-v4-flash-dhwork"
TOKEN=open("/tmp/t_dhwork.txt").read().strip()
TARGET="/tmp/eng_demo_target.txt"

def chat(messages, tools=None, max_tokens=1500):
    p={"model":MODEL,"messages":messages,"max_tokens":max_tokens,"temperature":0.2}
    if tools: p["tools"]=tools; p["tool_choice"]="auto"
    req=urllib.request.Request(BASE+"/chat/completions",data=json.dumps(p).encode(),
        headers={"Authorization":"Bearer "+TOKEN,"Content-Type":"application/json"})
    with urllib.request.urlopen(req,timeout=120) as r:
        return json.loads(r.read().decode())

# ---------- 1) 工具：区分"安全/风险"等级 ----------
_fail_once={"n":0}
def read_file():
    return open(TARGET,encoding="utf-8").read() if os.path.exists(TARGET) else "文件不存在"
def append_line(text):
    _fail_once["n"]+=1
    if _fail_once["n"]==1:                 # 模拟一次性瞬时故障，用来演示重试
        raise RuntimeError("模拟瞬时 IO 故障(第一次)")
    with open(TARGET,"a",encoding="utf-8") as f: f.write(text+"\n")
    return f"已追加：{text}"
REGISTRY={
 "read_file":  {"fn":lambda **k: read_file(),      "risk":"low",   "args":{}},
 "append_line":{"fn":lambda text: append_line(text),"risk":"write","args":{"text":"要追加的一行"}},
}
TOOL_SCHEMA=[{"type":"function","function":{"name":n,
  "description":("读取目标文件内容") if n=="read_file" else "向目标文件追加一行（写操作，有副作用）",
  "parameters":{"type":"object","properties":v["args"] or {},"required":list(v["args"].keys())}}}
  for n,v in REGISTRY.items()]

# ---------- 2) HITL 审批门（模拟：第一次拒绝，之后同意） ----------
def human_approve(tool,args):
    print(f"  [HITL] 待批准: {tool}({args}) ... 模拟人工第一次拒绝、第二次同意")
    human_approve.calls+=1
    return human_approve.calls>=2
human_approve.calls=0

# ---------- 3) 可观测：结构化 Trace ----------
TRACE=[]
def span(name, **kw):
    rec={"ts":round(time.time(),3),"span":name}; rec.update(kw)
    TRACE.append(rec); print("  [trace]", json.dumps(rec,ensure_ascii=False))

# ---------- 4) 带重试 + 审批 + 超时 的受控工具执行 ----------
def safe_call(name, args, retries=2):
    spec=REGISTRY[name]
    if spec["risk"]=="write" and not human_approve(name,args):
        span("tool_denied", tool=name, reason="未获人工批准"); return "已被人工拒绝，未执行。"
    for attempt in range(1,retries+1):
        t0=time.time()
        try:
            out=spec["fn"](**args)
            span("tool_ok", tool=name, attempt=attempt, ms=int((time.time()-t0)*1000)); return out
        except Exception as e:
            span("tool_retry", tool=name, attempt=attempt, err=str(e)[:60]); time.sleep(0.5)
    span("tool_fail", tool=name); return "工具重试耗尽仍失败。"

GOAL="把『今天学了 Agent 工程化护栏』追加到目标文件，然后读回文件内容确认。"

# ---------- 5) 主循环：带预算刹车 ----------
BUDGET_STEPS=6; BUDGET_TOKENS=12000
used_tokens=0; steps=0; final=""
messages=[{"role":"system","content":"你可以调用工具完成任务；需要写文件时直接调用写工具。"
                                    "若写操作被人工拒绝，请再次调用同一写工具重试一次。"},
          {"role":"user","content":GOAL}]
while steps<BUDGET_STEPS:
    steps+=1
    r=chat(messages,tools=TOOL_SCHEMA)
    used_tokens+=r["usage"]["total_tokens"]; messages.append(r["choices"][0]["message"])
    tcs=r["choices"][0]["message"].get("tool_calls") or []
    span("llm_step", step=steps, tokens=r["usage"]["total_tokens"], budget_left=BUDGET_TOKENS-used_tokens)
    if used_tokens>=BUDGET_TOKENS: span("budget_stop", reason="token 预算耗尽"); break
    if not tcs:
        final=r["choices"][0]["message"].get("content",""); break
    for tc in tcs:
        fn=tc["function"]["name"]; args=json.loads(tc["function"]["arguments"] or "{}")
        obs=safe_call(fn,args)
        span("observation", tool=fn, out=str(obs)[:80])
        messages.append({"role":"tool","tool_call_id":tc["id"],"content":str(obs)})

print("最终回答:", (final or "（预算用尽，未产出终答）")[:300].replace("\n"," "))
print("步数:",steps,"| 累计 tokens:",used_tokens,"| trace 条数:",len(TRACE))
print("目标文件内容:", repr(open(TARGET,encoding="utf-8").read()) if os.path.exists(TARGET) else "不存在")
```

- **本机实测输出（2026-11-14 上午实跑，节选）**
  ```
    [trace] {"ts": ..., "span": "llm_step", "step": 1, "tokens": 686, "budget_left": 11314}
    [HITL] 待批准: append_line({'text': '今天学了 Agent 工程化护栏'}) ... 模拟人工第一次拒绝、第二次同意
    [trace] {"span": "tool_denied", "tool": "append_line", "reason": "未获人工批准"}
    [trace] {"span": "observation", "tool": "append_line", "out": "已被人工拒绝，未执行。"}
    [trace] {"span": "llm_step", "step": 2, "tokens": 590, "budget_left": 10724}
    [HITL] 待批准: append_line(...) ... （第二次：同意）
    [trace] {"span": "tool_retry", "tool": "append_line", "attempt": 1, "err": "模拟瞬时 IO 故障(第一次)"}
    [trace] {"span": "tool_ok", "tool": "append_line", "attempt": 2, "ms": 0}
    [trace] {"span": "observation", "tool": "append_line", "out": "已追加：今天学了 Agent 工程化护栏"}
    [trace] {"span": "llm_step", "step": 3, ...}
    [trace] {"span": "tool_ok", "tool": "read_file", "attempt": 1, "ms": 0}
    [trace] {"span": "observation", "tool": "read_file", "out": "今天学了 Agent 工程化护栏\n"}
    [trace] {"span": "llm_step", "step": 4, "tokens": 700, "budget_left": 9401}
  最终回答: 已完成。1. 已将『今天学了 Agent 工程化护栏』追加到目标文件（首次被拒绝，重试后成功）。
            2. 读回文件内容确认：今天学了 Agent 工程化护栏 …
  步数: 4 | 累计 tokens: 2599 | trace 条数: 11
  目标文件内容: '今天学了 Agent 工程化护栏\n'
  ```
  **一次运行看全了三种护栏**：**拒绝**（HITL，第 1 步）→ **审批通过后的瞬时故障重试**（可靠性）→ **read_file 读回确认**（闭环）→ 全程 **11 条 trace**（可观测）。

- **逐行要点**
  - `REGISTRY[...]["risk"]`：**给每个工具打风险标签**——这是 HITL 分级审批的根据，比"所有工具都弹窗"聪明得多。
  - `safe_call` 里 `if spec["risk"]=="write" and not human_approve(...)`：**写操作先过审批门**，未批准直接返回"已被拒绝"，**不执行、不编造**。
  - `for attempt in range(1,retries+1)`：**重试循环 + `time.sleep(0.5)` 退避**；成败都记 `span`。
  - `if used_tokens>=BUDGET_TOKENS: span("budget_stop"); break`：**预算刹车**——硬上限触发即停，并留下痕迹。
  - `span(...)` 每条都是**一行 JSON**——落成 `.jsonl` 文件就能被 ELK / OpenTelemetry 一类系统直接消费。
- **踩坑提示**
  1. **"被拒绝"必须是一等公民**：本次第 1 步被拒，模型**没有硬撑**而是被提示"重试一次"——若提示词不写清楚，模型很可能**编一句"已完成"**（幻觉）。**拒绝文案要写成"给模型的指令"**（接 11-11 的错误文案经验）。
  2. **写操作的重试要防重复**：这次 `append_line` 第一次"瞬时故障"时**其实已有可能写进去**（真实系统里半成功最可怕）。**生产里写工具必须幂等**（带 request_id / 先查后写 / 事务）。
  3. **预算要同时有"步数"和"token"两个闸**：只限步数挡不住单步超长；只限 token 挡不住空转。本次两个都设了。
  4. **trace 要能"回放"才有用**：只打印不够，**要落文件**（动手任务 2），否则出了问题你只有当场那一眼。
  5. **`human_approve.calls` 用的是函数属性**——Python 里简单好用，但多线程要小心；生产用独立计数器 / 状态机。

- **待复习（3 条，今天必须记住）**
  1. **三道护栏：可观测（结构化 trace）+ 可靠性（retry / timeout / 幂等 / 预算刹车）+ Human-in-the-loop（写操作审批门）**——缺一件都上不了生产。
  2. **"被拒绝"和"失败"必须让 Agent 诚实交还控制权**：未批准的写操作要返回"已被拒绝、未执行"，**绝不允许模型编一个"已完成"**（EvoX 论文点名的 "unsupported completion claims"）。
  3. **写操作重试必须幂等**：本次 `append_line` 的"瞬时故障"在真实系统里可能已经半成功——**没有幂等 ID，重试就会写重复**。
- **一句话复盘**：最容易忘的是——**Agent 工程化的价值不在"让它更聪明"，而在"让它出错时你能接得住"**：看得见（trace）、扛得住（重试/刹车）、管得住（审批），这三件事你写 Android 时早就会了，搬过来即可。
