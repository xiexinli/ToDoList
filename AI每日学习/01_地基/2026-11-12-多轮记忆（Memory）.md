## 1 概念精讲（30 min）

**一句话定义**
多轮记忆 = 在**有限的上下文窗口**里，尽量让模型"看起来记得住一切"（用户偏好、历史事实、跨会话信息），同时对"每轮都要重放历史"这个成本做**分层治理**。

**它解决什么问题 / 为什么现在必须懂**
1. **昨天（11-11）你已经看到病根**：ReAct 每轮都把**全部历史**重新发一遍，5 轮累计 2743 tokens——**步数一多、轮次一长，成本是平方级增长**。
2. **窗口装不下**：会话再长一点，"原样重放"必然撞上下文上限（对接 11-11 的 max_steps 刹车）。
3. **跨会话会失忆**：用户上周说的"我花生过敏"，今天新开会话就没了——这不是窗口问题，是**没有长期记忆**。
4. **记忆是 Agent 从"玩具"到"产品"的分水岭**：客服、私人助理、编码助手，决定体验好坏的往往不是模型多聪明，而是"它记不记得我是谁"。

**关键机制：三层记忆**

```
        一问一答持续进行
              │
    ┌─────────┴──────────┐
    ▼                    ▼
①短期窗口            ②滚动摘要                ③长期记忆库
最近 N 轮原样保留     更早的对话用 LLM          跨会话的结构化事实
（保证指代/语气连贯）  压成 ≤60 字事实摘要        （键值 / 向量库）
    │                    │                        │
    └────────┬───────────┴───────────┬────────────┘
             ▼                       ▼
        组装成本轮 prompt：System + 【历史摘要】 + 【相关长期记忆】 + 最近N轮 + 本轮问题
```

- **短期窗口**：解决"指代与连贯"——"它/那个/上次说的坑"必须能在最近几轮里找到指代对象。
- **滚动摘要**：解决"长度"——把已结束的话题压成事实（人名、偏好、约束），丢弃寒暄。**摘要是一次性成本，之后每轮都省。**
- **长期记忆库**：解决"跨会话"——事实以结构化形式存外部（数据库 / 向量库 / 文件），**每轮按当前问题检索 top-k 注入**（这里的"检索"就是 11-07 ~ 11-09 学的 RAG 那套，记忆库 ≈ 一个小的私有知识库）。

**常见误区**
1. **很多人以为"记忆 = 把历史全塞进 prompt"**——其实那只是"短期窗口取无穷大"，既不经济也撞上限；真正的记忆是**分层 + 检索**。
2. **很多人以为"接了向量库就等于有记忆"**——其实还得解决**何时写入**（哪句话值得记？）、**何时更新**（新事实覆盖旧事实）、**何时遗忘**（过期的删掉）。写/读/改/删四个动作都要设计。
3. **很多人以为"摘要做一次就够了"**——其实摘要是**滚动**的：新的一批旧对话要并进现有摘要（否则摘要永远停在最早的几轮）。
4. **很多人以为"摘要一定无损"**——其实摘要会丢细节。**关键约束（过敏、金额、法务条款）应进长期记忆库原样保存，不要只靠摘要。**

## 2 代码片段（40 min）

- **场景**：同一段 6 轮历史对话 + 一个新问题，用两种记忆策略各答一次，**量出 prompt_tokens 差异**，验证"分层记忆"不是玄学。
- **依赖与版本**：仅 Python 3 标准库（`urllib`/`json`/`re`）；模型走本机 DHwork OpenAI 兼容端点（`https://www.dhcoder.net/llm-api/v1`，模型 `deepseek-v4-flash-dhwork`）。本机 python3 为 3.9.6，无需额外安装。

```python
# -*- coding: utf-8 -*-
# memory_demo.py —— 三种记忆策略的 token 对比（真实调用本机 DHwork 端点）
import json, urllib.request, re

BASE = "https://www.dhcoder.net/llm-api/v1"
MODEL = "deepseek-v4-flash-dhwork"
TOKEN = open("/tmp/t_dhwork.txt").read().strip()   # 令牌抽取见文末"踩坑提示"

def chat(messages, max_tokens=1500, temperature=0.2):
    body = json.dumps({"model": MODEL, "messages": messages,
                       "max_tokens": max_tokens, "temperature": temperature}).encode()
    req = urllib.request.Request(BASE + "/chat/completions", data=body,
        headers={"Authorization": "Bearer " + TOKEN, "Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=90) as r:
        return json.loads(r.read().decode())

SYSTEM = "你是一位严谨的私人助理，回答时严格依据已知信息，不知道就说不知道。"

# ---- 一段 6 轮的"历史对话"（模拟真实会话） ----
history = [
    ("user", "我下周三要去上海出差，帮我记一下。"),
    ("assistant", "好的，已记录：下周三上海出差。"),
    ("user", "我的常用邮箱是 alion@example.com，报销的东西都发我邮箱。"),
    ("assistant", "好的，已记录：报销材料发到 alion@example.com。"),
    ("user", "另外我对花生过敏，帮我订餐时避开。"),
    ("assistant", "好的，已记录：你对花生过敏。"),
    ("user", "公司报销标准：高铁二等座、酒店每晚不超过 600 元。"),
    ("assistant", "好的，已记录报销标准：高铁二等座、酒店≤600/晚。"),
    ("user", "上次我住的是虹桥附近那家，房间有点吵。"),
    ("assistant", "记下了：虹桥附近那家酒店较吵，下次可换。"),
    ("user", "好了先这样。"),
    ("assistant", "好的，随时叫我。"),
]
NEW_Q = "帮我订下周三上海出差的行程，注意别踩我上次说过的坑。"

# ---- 长期记忆库（结构化事实） ----
facts = {
    "行程": "下周三上海出差",
    "邮箱": "alion@example.com（报销材料发此邮箱）",
    "过敏": "对花生过敏，订餐需避开",
    "报销标准": "高铁二等座、酒店每晚≤600元",
    "住宿偏好": "上次住虹桥附近较吵，尽量避开",
}

# ---- 策略 A：全量重放（把整段历史原样塞进 prompt） ----
msgs_full = [{"role": "system", "content": SYSTEM}] + \
            [{"role": r, "content": c} for r, c in history] + \
            [{"role": "user", "content": NEW_Q}]
rA = chat(msgs_full, max_tokens=1500)

# ---- 策略 B：窗口 + 滚动摘要 + 相关长期记忆 ----
def summarize(turns):
    txt = "\n".join(f"{r}: {c}" for r, c in turns)
    r = chat([{"role": "user",
               "content": "把下面这段对话压成不超过 60 字的事实摘要，只保留长期有用的事实（人名/偏好/约束），不要寒暄：\n\n" + txt}],
             max_tokens=800)     # 注意：推理模型预算给太小会返回空串（见踩坑3）
    return r["choices"][0]["message"]["content"].strip()

recent = history[-4:]          # 最近 2 轮原样保留
older  = history[:-4]
rolling = summarize(older)     # 更早的压成摘要（一次性成本）

# 简易"长期记忆检索"：按问题关键词命中 facts
hit = {k: v for k, v in facts.items()
       if any(ch in NEW_Q for ch in k) or k in ("过敏", "报销标准")}
facts_txt = "；".join(f"{k}:{v}" for k, v in hit.items())

msgs_mem = [{"role": "system", "content": SYSTEM},
            {"role": "system", "content": "【历史摘要】" + rolling},
            {"role": "system", "content": "【相关长期记忆】" + facts_txt}] + \
           [{"role": r, "content": c} for r, c in recent] + \
           [{"role": "user", "content": NEW_Q}]
rB = chat(msgs_mem, max_tokens=1500)

uA, uB = rA["usage"], rB["usage"]
print("策略A 全量重放   prompt_tokens =", uA["prompt_tokens"])
print("策略B 窗口+摘要   prompt_tokens =", uB["prompt_tokens"])
print("摘要:", rolling)
print("命中长期记忆:", list(hit.keys()))
print(f"省下 prompt_tokens: {uA['prompt_tokens']-uB['prompt_tokens']} "
      f"({(1-uB['prompt_tokens']/uA['prompt_tokens'])*100:.0f}%)")
```

- **本机实测输出（2026-11-14 上午实跑）**
  ```
  === 策略 A：全量重放 ===
    prompt_tokens = 288 | completion = 1441
    回答: 好的，已开始按您的要求安排下周三上海出差：交通：订高铁二等座（符合报销标准）。
          住宿：避开上次虹桥那家较吵的酒店，选择预算≤600元/晚、评价安静的酒店。餐饮：订餐时备注花生过敏…
  === 策略 B：窗口 + 摘要 + 长期记忆 ===
    prompt_tokens = 243 | completion = 404
    摘要: 出差：下周三上海。常用邮箱：alion@example.com，报销材料发此邮箱。忌口：花生过敏。报销标准：高铁二等座，酒店≤600元/晚。
    命中长期记忆: ['行程', '过敏', '报销标准']
    回答: 好的，我来按您的要求安排下周三（上海）的行程，确保避开已知问题：1. 住宿：避开虹桥附近那家吵的酒店…
  === 对比 ===
    省下 prompt_tokens: 45 (16%)
  ```
  **两个回答都完整命中了"过敏、报销标准、避开吵的酒店"**——省 token 的同时没有掉信息，这才是记忆管理的目标。

- **逐行要点**
  - `recent = history[-4:]`：**窗口只留最近 2 轮**——保证指代连贯，其余全部可丢。
  - `summarize(older)`：把更早的对话压成事实摘要，**这是一次性成本**，之后每轮复用。
  - `hit = {...}`：模拟"长期记忆检索"——真实系统里这一步是**向量检索 top-k**（接 11-07/11-08 的 embedding/rerank），本讲用关键词命中做最小演示。
  - 三段组装顺序：**System → 历史摘要 → 相关长期记忆 → 最近窗口 → 本轮问题**，把"长期"放前面、"最近"贴近问题，模型对最近的更敏感。
- **踩坑提示**
  1. **"记忆"这个词会骗人**：`facts` 字典不是记忆的全部——真实系统还要处理**写入时机**（哪句值得记）和**冲突覆盖**（新地址覆盖旧地址）。本讲只演示"读"，写/改/删是动手任务。
  2. **16% 只是开头**：历史只有 6 轮时收益不大；**收益随轮数增长而放大**，因为策略 A 是 O(历史长度)、策略 B 的窗口是 O(1)。真正的杀手锏是**跨会话**——策略 B 的事实库在新会话里照样注入，策略 A 直接归零。
  3. **推理模型的预算陷阱（本次真实踩到）**：`summarize` 一开始给 `max_tokens=150`，模型把预算全花在推理上、**正文返回空串**；改成 `800` 才稳定出摘要。回想 11-05 的记录：推理模型 `max_tokens` 是"推理 + 正文"共享预算——**凡是要它输出内容，就别给太小**。
  4. **摘要长度会影响收益**：本次摘要 60 字左右，若摘要写得又长又啰嗦，省下的 token 会被吃回去——**摘要要"压缩率优先"，宁短勿全**。

## 5 明日预告与待复习（8 min）

- **明日主题**：W4 第 3 讲——**规划与任务分解（Planning）**：ReAct 是"走一步看一步"，但复杂任务得**先出计划再执行**。明天学 Plan-and-Execute：先让规划器把目标拆成有序子步骤，执行器逐步跑，失败就**重规划**。
- **待复习（3 条，今天必须记住）**
  1. **三层记忆 = 短期窗口（连贯）+ 滚动摘要（省长度）+ 长期记忆库（跨会话，按需检索注入）**；组装顺序：System → 摘要 → 相关长期记忆 → 最近窗口 → 本轮问题。
  2. **摘要是一次性成本、窗口是 O(1)**：本讲实测全量重放 288 vs 分层 243 tokens（省 16%），历史越长、跨会话越多，差距越大。
  3. **推理模型 max_tokens 是"推理+正文"共享预算**：`summarize` 给 150 时正文返回空串，给 800 才稳——输出内容的调用别把预算抠太紧。
- **一句话复盘**：最容易忘的是——**记忆的难点不在"存"而在"写什么、何时覆盖、何时忘"**；今天只演示了"读"，真正的产品化功夫在写入治理上。
- **附**：本文全部实测来自 2026-11-14 上午本机实跑（脚本 `/tmp/mem_demo.py`：策略 A/B 各 1 次 + 摘要 1 次，共 3 次 LLM 调用）。
