# 第五部分：推荐学习路线

## 阶段 0：编程与工程基础

学习：

- Git；
- Node.js 或 Python；
- JSON、HTTP；
- 包管理；
- 环境变量；
- 命令行和日志。

练习：写一个接收文本、输出 JSON 的小程序。

## 阶段 1：需求与 AC

学习：

- EARS；
- AC；
- 正常、边界、异常样本；
- 基础追溯表。

练习：为“文本摘要助手”写 3 条 EARS、5 条 AC 和对应测试样本。

## 阶段 2：TDD 与分层

学习：

- Red-Green-Refactor；
- Fake；
- 测试契约；
- `lib / adapters / 外壳`。

练习：实现一个不连接真实服务的订单状态解释器，覆盖成功、未找到、超时。

## 阶段 3：LLM 与工具调用

学习：

- Prompt 基础；
- 结构化输出；
- Tool Calling；
- 参数校验；
- 失败处理。

练习：让 LLM 判断是否需要调用一个只读 Fake 工具。

## 阶段 4：Web MVP

学习：

- 页面最小闭环；
- 加载、成功、失败状态；
- Web 与 lib 解耦；
- 拓扑选择。

练习：做一个输入框、提交按钮、结果区域和错误提示。

## 阶段 5：Agent、编排与审批

学习：

- Agent 状态；
- 编排器；
- Guardrail；
- HITL；
- interactive/yolo。

练习：实现“查询 → 生成建议 → 等待审批 → 执行”的流程。

## 阶段 6：Real、Live、Eval 和 CI

学习：

- SDK 探针；
- Real 集成；
- Live Eval；
- CI 质量门禁；
- AC 状态统计。

练习：给项目补一个 SDK 探针、一份 Live Eval 记录和一个最小 CI。

## 阶段 7：MCP 与复用

学习：

- MCP；
- 工具协议；
- 脚手架；
- Skill 设计；
- 模板化交付。

练习：把一个已完成的小项目沉淀为“工具接口 + Fake + 契约测试 + Demo 模板 + 安装脚本”。

# 第六部分：推荐综合练习

## 题目：受控的订单查询与处理建议助手

> 使用合成数据或 Fake 服务，不假设真实订单系统和权限。

### 最小功能

```text
输入订单号
  → 判断输入是否完整
  → 调用只读订单工具
  → 返回状态解释
  → 对未找到、超时等情况安全降级
  → 涉及写操作时等待人工审批
```

### 概念覆盖

| 功能层 | 学习概念 |
|---|---|
| 需求 | EARS、AC、追溯 |
| 核心逻辑 | lib、TDD |
| 外部接入 | adapters、Tool Calling、MCP |
| AI 能力 | LLM、Agent、编排器 |
| 风险控制 | Guardrail、HITL |
| 数据与评估 | Fake、Real、Live、合成样本、Live Eval |
| 交付 | Web MVP、CLI、CI、Demo |
| 复用 | 脚手架、Skill |

### 建议目录

```text
project/
├─ docs/
│  ├─ requirements.md
│  ├─ traceability.md
│  └─ live-eval.md
├─ src/
│  ├─ lib/
│  ├─ adapters/
│  ├─ app/
│  └─ cli/
├─ tests/
│  ├─ unit/
│  ├─ contract/
│  └─ integration/
├─ samples/
└─ scripts/
```

# 第七部分：初学者常见误区

## 误区 1：会调用 LLM 就等于会做 AI 开发

调用模型只是起点。还需要工具、规则、测试、权限、失败处理、评估和交付。

## 误区 2：Agent 越自主越好

自主程度应匹配风险、可逆性、权限和验证能力。

## 误区 3：Fake 全绿就能上线

Fake、Real、Live 分别验证不同层面，不能互相替代。

## 误区 4：所有业务规则都写进 Prompt

权限、金额、状态机、审批和不可违反的规则应优先放在可测试代码中。

## 误区 5：先做复杂页面

先完成一条最小用户路径：

```text
输入 → 处理 → 结果 → 失败提示
```

## 误区 6：把 Guardrail 当成敏感词过滤

真正的 Guardrail 还包括权限、工具白名单、参数校验、审批和停止条件。

## 误区 7：把 Skill 当成普通说明文档

Skill 应当包含流程、模板、脚本和验证方法，能够指导实际执行。

# 最后自测：是否真正理解了 AI 应用开发

尝试回答以下问题：

1. LLM 和 Agent 的边界是什么？
2. 为什么工具调用不能完全由模型直接执行？
3. MCP 与工具调用分别解决什么问题？
4. 为什么 Fake 测试不能替代 Live Eval？
5. 哪些规则应该放在代码而不是 Prompt？
6. 什么时候应该引入 HITL？
7. 一条 EARS 如何转化为 AC 和测试？
8. 为什么要把核心逻辑放进 lib？
9. Web MVP 和“做一个漂亮页面”有什么区别？
10. 脚手架和 Skill 分别复用了什么？

如果能够完整回答并亲手完成综合练习，就已经从“会用模型”进入了“会构建可验证 AI 系统”的阶段。
